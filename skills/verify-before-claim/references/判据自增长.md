# 判据自增长（三层自适配机制）

> 本文件是 `SKILL.md`「依赖」里两个自适配脚本的展开层：SKILL.md 只给结论与指针，
> 落到「具体怎么生成指纹、怎么入库一条判据」时读这里。

假成功形态**跨环境通用**，但「哪条判据会在本机命中」是**个性化**的。
本技能用三层机制承接这两面：**层 1 指纹**回答"这台机器的判读规则是什么"，
**层 2 入库门**回答"一条新判据凭什么进来"，**层 3 保留集**回答"它进来之后有没有把旧的挤坏"。

---

## 一、三层总览

| 层 | 做什么 | 脚本 | 触发时机 |
|:--:|---|---|---|
| **1 环境指纹** | 探测本机环境特征，对齐到判据库，列出「本机已确认的陷阱」 | `scripts/env_fingerprint.py` | 换机器 / 换环境后首次验证；或要判断跨环境可比性时 |
| **2 入库门** | 候选判据须**实跑反例并报出 FAIL** 才允许入库 | `scripts/candidate_gate.py` | 每次从一次真实踩坑沉淀出新判据时 |
| **3 保留集回归** | 既有判据与全部脚本自检重跑一遍，全绿才允许入库 | `scripts/candidate_gate.py regress` | 每次入库**之前** |

三层的共同点：**每一层的输出都是可机械判定的**（指纹项只有 true / false / unknown；
入库门只有过 / 不过；回归只有全绿 / 不绿）。没有一层依赖"看起来差不多"。

## 二、层 1 · 环境指纹

### 2.1 基本用法

```bash
python3 scripts/env_fingerprint.py                 # 打印报告（默认不写文件）
python3 scripts/env_fingerprint.py --json          # 机器可读
python3 scripts/env_fingerprint.py --save ~/env.json   # 存基线
python3 scripts/env_fingerprint.py --diff A.json B.json  # 比对两份
python3 scripts/env_fingerprint.py --self-test     # 阴性对照
```

### 2.2 每一项只有三种取值，且 `unknown` 不能被当 `false`

| 取值 | 含义 | 处置 |
|---|---|---|
| `true` / `false` | 探测跑通了，拿到了事实 | 按对齐结论走 |
| **`unknown`** | **探测没跑起来** | 该判据在本环境的适用性**未验证**，须换通道或显式写"未验证" |

⚠️ 这是第 6 类失败形态（探测失败 ≠ 对象不可用）在指纹层面的复现：
**把「探测不到」写成「这个特性不支持」，就得到一份看起来完整、实际是猜的指纹。**
`--self-test` 会用一个 PATH 置空的受限环境证明本脚本确实报 `unknown`。

### 2.3 对齐输出读三栏，不要只读第一栏

| 栏 | 含义 | 常见误读 |
|---|---|---|
| 本机已确认的陷阱 | 该判据在此环境**成立**，照它处置 | — |
| **本环境不成立** | 该判据的现象在此环境**实测不出现** | ⚠️ 被读成"这条判据没用" —— 错。它只是**在此环境**不出现，换环境即翻转；且判据里的**建议**（如一律 `grep -E`）通常仍成立 |
| 未验证项 | 探测没跑起来 | ⚠️ 被读成"不适用" —— 错，它是**没验证** |

> 实例：在 Darwin + `BSD grep 2.6.0-FreeBSD`（**GNU compatible**）上，
> `printf 'a\nb\n' | grep -c 'a\|b'` 返回 **2**，即**支持** BRE 交替 ——
> 与 **L02** 记录的形态相反。这正是"照抄个性化判据"会被实测打脸的例子（判据 **L40**）。
> 结论**不是** L02 没用，而是：**在本机不成立，换环境须复测**。

### 2.4 存到哪（**不要进技能目录**）

指纹是**本机专属的过程数据**，含平台、shell、工具集。默认只打印；要留档显式给 `--save`。
建议存到技能目录**之外**（如 `~/.workbuddy/state/verify-before-claim/`）——
技能目录会被打包发布，本机指纹既不该进包，也不该外传。

### 2.5 跨环境沿用（`--diff`）

- **关键项**（os / arch / shell / grep 方言 / `/dev/tcp` / 进程列表 / python3 / UTC 偏移 + 关键工具）
  有差异 ⇒ **rc=2**：在 A 上采集的结论**不可直接沿用到 B**，旧结论降级为**「无法判定」**，在 B 上重跑。
- **次要项**有差异 ⇒ 提示，通常仍可比。
- ⚠️ **关键项清单是通用的**：`wget` / 代理变量 / 凭据代理按次要项计 —— 若某份证据恰好依赖它们，比对会误判「可比」（判据 R35）。处置：**把该证据实际依赖的命令补进关键项再比对**。
- 任一侧是 `unknown` ⇒ 按关键差异计（可比性下降）。

## 三、层 2 · 候选判据入库门

### 3.1 完整流程（半自动）

```bash
# 1) 生成骨架
python3 scripts/candidate_gate.py new --code L42 --title "标题" --out cand.md

# 2) 静态检查（不执行命令）
python3 scripts/candidate_gate.py check cand.md

# 3) 入库门：实跑反例，必须报出 FAIL 信号
python3 scripts/candidate_gate.py verify cand.md

# 4) 保留集回归（层 3）
python3 scripts/candidate_gate.py regress

# 5) 入库（默认 dry-run；--apply 才真写 —— 这一下是人工过闸）
python3 scripts/candidate_gate.py admit cand.md --apply
```

### 3.2 三条硬规则

1. **编号接末尾，不重排** —— 编号是稳定标识符，外部笔记按编号引用单条判据。
   冲突 ⇒ 直接拒（`check` 阶段）。
2. **反例必须实跑出 FAIL 信号** —— 静态看着像反例不算。
3. **来源必须留档** —— `来源事件` / `来源日期` / `原始输出`；**拒绝推测型判据**。
   「我觉得应该会有这种情况」不是判据，是猜想。

### 3.3 反例命令的两个占位与三种判定

| 项 | 写法 |
|---|---|
| 占位 | `{tmp}` = 临时工作目录；`{skill}` = 技能目录 |
| **`nonzero`**（默认） | 命令**非零退出** ⇒ FAIL 信号 |
| `rc:N` | 退出码**等于** N ⇒ FAIL 信号 |
| `nomatch:正则` | 命令正常返回但输出**不含**该正则 ⇒ FAIL 信号 |

⚠️ **命令跑不起来不算 FAIL 信号**：rc=127 / 超时 / `command not found`
一律判"未产生 FAIL 信号"并拒绝入库。它与「反例如期报错」在退出码上**同形**，
是最容易蒙混过关的一种（判据 **L41**）。

### 3.4 `admit` 做了什么 / 没做什么

| 做了 | 没做（留给人工） |
|---|---|
| 按 `--section`（或类别续节）插入、更新标题「（N 条）」、把节标题编号范围上界推到新编号 | **不**自动新建类目节；**不**判断这条判据值不值得留；**不**替你过闸 |

> `--apply` 之所以要人显式敲出来，不是技术限制——文献对"全自动改写判据库"的警告很明确：
> 对抗性输入会持续触发特定方向的改写，**渐进劣化且难被发现**。
> 脚本负责**守住门**，人负责**决定要不要过**。

## 四、层 3 · 固定保留集回归

`regress` 依次重跑四项，**全绿才允许入库**：

| # | 保留项 | 它守住什么 |
|:--:|---|---|
| 1 | `assert_hits.py` | 判据条数、七类覆盖、每条三段齐备 |
| 2 | `assert_hits.py --self-test` | 判据库自检**自己**能报 FAIL |
| 3 | `evidence_pack.py --self-test` | 证据包能识别缺陷样本 |
| 4 | `env_fingerprint.py --self-test` | 指纹能报 unknown、比对能报差异 |

对应文献里的"灾难性遗忘"闸门：新判据进来后，旧判据的有效性必须**重新被证明一遍**，
不能假设它还在。

## 五、五道闸门与显式盲区

| 风险（文献） | 闸门（本技能） |
|---|---|
| 灾难性遗忘（新的挤掉旧的） | 固定保留集回归全绿才入库 |
| 反馈投毒 / 审查者橡皮图章 | 只接受**有实证来源**的候选（日期 + 命令 + 原始输出），拒绝推测型 |
| 治理缺口（更新无法追责） | 每条新判据存档来源事件 / 入库时的阴性对照输出 |
| 渐进劣化且难发现 | **半自动 + 人工过闸**；变更集可整体回滚（快照） |
| 合成测试只能捕获可预见的失败 | **不宣称覆盖全部幻觉**，盲区显式标注 |
| **自审自验同源**（整库与脚本由同一条链路自己证明自己） | **每完成一轮增补，必经一次「换家族独立复审」**：由另一条独立链路（不同模型家族 / 不同会话）**只读**跑一遍保留集与反向验收；复审方**不改动被审目录**，只出建议 |

> ⚠️ **最后一行是最后补上的，也是最容易被跳过的**：入库门缓解的是「可疑判据进来」，
> 缓解不了「**整个判据库与脚本由同一个人在同一条链路上自证**」。真正的解药是换家族那一层——
> 而它一旦「靠人想起来才做」，就等于没有 —— 所以**写进流程**：每轮增补的收尾 = 归档 + **换家族独立复审**。

**显式盲区（必须承认，不得含糊）**：

1. 指纹只探测**已知会影响判读的维度**；未列入的维度差异（如某个特定工具的补丁版本）不会出现在比对里。
2. 入库门只证明**反例在这一刻、这台机器上跑得出 FAIL**；它不证明该判据在别处也成立
   —— 这正是层 1 要补的另一半。
3. 保留集回归只能抓住**已被旧断言覆盖**的退化；旧断言本身没覆盖的损失，回归同样是绿的。
4. **「编号 ↔ 内容」没有基线**：把两条判据的编号互换，自检**不会**报错 —— 外部笔记按编号引用时会静默指向别的内容。本库不做内容哈希基线，靠的是「编号接末尾、禁重排」这条纪律；引用方**应连同标题一起引用**（如「L40 照抄个性化判据」）。
5. **存量判据多数只有描述性反例**：它们写的是**可人工照做的描述**，没有可直接复跑的命令行（判据库所称「自带反例」同时含这两类），`regress` 因而只能复跑带「反例命令」字段的条目，其余靠人工按描述做对照 —— 这是已知的能力缺口，不是已覆盖。

## 六、常见错误（自适配相关）

| 错误 | 正解 |
|---|---|
| 把「本环境不成立」当成"这条判据没用" | 它只是**在此环境**不出现；建议通常仍成立，换环境须复测（L40） |
| 把 `unknown` 读成"不支持" | 那是**没验证**；换通道或显式写未验证（第 6 类） |
| 反例命令跑不起来（rc=127）却算通过 | 跑不起来 ≠ 反例生效，必须拒（L41） |
| 沿用别机的证据不比对指纹 | 关键项有差异 ⇒ 旧结论降级为无法判定并在本地重跑（R35） |
| 新判据先入库、反例以后再补 | 反例没实跑过就不入库；跑不出就进待修清单 |
| 把 `admit --apply` 挂进自动化 | 那是人工过闸点；自动化只应跑到 `verify` |
| 指纹存进技能目录 | 会被打包发布；存到技能目录之外 |
