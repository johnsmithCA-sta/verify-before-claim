# 判据库 · 远端与接口（35 条）

> 用法同《判据库-本机与工具链》：**现象 → 判据 → 反例**，反例必须能跑出 FAIL。
> 归类编号对应 SKILL.md 的七类失败形态表；第 6 类（**探测失败 ≠ 对象不可用**）集中在本文件 R14–R21，第 7 类（远端侧）R27–R29，**类 3 续「通道相关与聚合失效」与类 7 续「证据不可复跑」一并附于文件末尾（各节标题自带编号范围）**。

## 类 4 · HTTP 200 ≠ 正确内容（R01–R06）

### R01 错误页也是 200
- **现象**：下载接口的签名偶发失效，返回体是一段错误 XML（约 542 B），**HTTP 状态码仍是 200**。只看状态码或只看退出码（`$?` = 0）会把错误页当文件比对，进而把 4,634 B 的真文件判成「平台只有 542 B」。
- **判据**：下载后先看**响应体开头**——不是预期格式即判失败，重新取链接；文件名 / 字节数 / 内容三者都要对。
- **反例**：故意用一个无效签名请求同一接口 —— 它同样返回 200，此时若你的校验仍报「下载成功」，即证明状态码不可作判据。

### R02 对象存储签名的前导斜杠
- **现象**：上传链路某一步报签名不匹配（403）。真因是签名对象键必须带**前导斜杠**，直接用返回的键原值签名必失败。
- **判据**：403 时先读响应体里回吐的待签字符串，**逐字节比对**与本地构造的差异，而不是先怀疑凭据无效。
- **反例**：同一对象分别用「带前导斜杠」与「不带」两种键签名 —— 只有一种通过，即可定位到本判据。

### R03 签名窗口的起点在未来
- **现象**：拿到上传凭证后**立刻**发起请求报「凭证无效」，被读成权限 / 凭据坏了。实际返回的授权串里时间窗口起点约为申请时刻 **+120~180 秒**（防时钟漂移）；在窗口开始前调用必然失败，且**每重新申请一次，起点又往后推约两分钟**。
- **判据**：把窗口起点换算成本地时间，晚于当前时间就是「还没生效」——**等过去再发**，最省事；不要反复重申请。
- **反例**：记录一次窗口起点，`sleep` 越过它再发 —— 从失败变成功即证明前一次失败与凭据无关。

### R04 前端是纯单页应用 ⇒ 状态码不能验链接
- **现象**：某平台网页端是 SPA，**任何路径都返回 200**（包括不存在的资源）⇒ 用请求状态码验证「某个深链是否存在」**恒为真**，得不出任何结论。
- **判据**：验证资源存在改用**数据接口**（返回结构化列表）或实际调用（能否安装 / 下载）；不把猜测的深链写进对外文档。
- **反例**：拼一个**必然不存在**的路径请求同一站点 —— 仍返 200，即证明该判据无效。

### R05 接口返回的「链接字段」是构造值
- **现象**：接口返回体里的主页字段看着像一个可访问 URL，实际直接请求返回 405——**它是拼出来的，不代表存在可用页面**。
- **判据**：任何要写进对外文档的链接，**先亲自请求一次**确认它可用；用「调用命令」这类可复制、可执行的文本替代不可靠深链。
- **反例**：对该字段值直接发起请求 —— 非 2xx 即证明它是构造值，不可对外。

### R06 官方文档给的地址命名规则不可信
- **现象**：按文档的命名规则拼服务地址，长期连不上；真实地址形态是「账号 ID + 随机串 + 地域」，**只能从接口返回里读**。
- **判据**：地址 / 端点 / 域名一律以**接口或控制台的实际返回**为准，文档规则只作理解用。
- **反例**：把「按文档拼出的地址」与「接口返回的地址」并列请求 —— 两者不等价即证明不能拼。

## 类 5 · 元数据 ≠ 实体（R07–R13）

### R07 列表接口的体积字段是缓存
- **现象**：覆盖上传后，列表接口的 size 字段**仍显示旧值**（时间字段是新的），据此判「没生效」或「已生效」都会错。
- **判据**：判是否真的替换，**只能下载实体**：比字节数 + 检索只有新版才有的标记串。
- **反例**：上传一份内容必然变化的文件，上传后立刻读列表里的 size —— 若它没变，即证明该字段不能用于本次判定。

### R08 批量操作会刷平时间字段
- **现象**：批量移动 / 批量修改会把整批条目的更新时间**刷成同一分钟**，于是「谁更新」这个判断彻底失效（不同批次各自被刷平）。
- **判据**：判内容新旧**回读正文做指纹比对**（长度 / 字数 / 章节结构 / 关键串），不看时间字段。
- **反例**：对两个**内容不同、时间被刷平**的条目跑你的新旧判定 —— 判不出即证明判据错。

### R09 「已上架」不能只看名称能搜到
- **现象**：检索命中只说明平台上**有这个名字**，不说明平台上的是你手上这一版；提交后本地继续改不会自动同步。实测出现过平台包与本地包体积差 10 KB、且恰好缺三样针对性的防线。
- **判据**：把平台包**拉下来逐文件比对**：哈希 + 字节数 + **章节结构**（标题列表最直观）三方。
- **反例**：拿一个**刚新增、尚未提交**的章节标题去平台包里查 —— 查不到即证明你在比对本地；查得到才是真上线。

### R10 访问统计只保留固定天数
- **现象**：流量接口只保留约两周，不落盘则历史**永久丢失、无法环比**。
- **判据**：周期性存档（周存档最省事），把归档当唯一历史源。
- **反例**：取一次两周前的数据 —— 取不到即证明不落盘就没有历史。

### R11 「本地是源稿所以领先」是错的假设
- **现象**：默认本地文档是「源」、线上是「旧版」，于是不做比对直接推送。实测真撞过**线上已含第二轮实证、而本地源稿还停在上一节**的情况。
- **判据**：上传前**回读线上最新版做指纹比对**（去格式标签后逐句查本地是否命中）；未命中的句子分三类：已被证伪的旧结论（不回带）/ 线上维护注记（吸收）/ 版本与标题差异（正常）。
- **反例**：把线上正文去标签后与本地逐句比对 —— 若存在**本地没有、也不属于上述三类**的句子，即证明本地落后。

### R12 被保护规则锁定的标签：打标前必须冻结产物
- **现象**：标签一旦受「禁止删除 + 禁止强推」规则保护，发布后要改内容**无解**，只能靠后续提交追平，标签永远停在旧提交。
- **判据**：打标**之前**把所有产物冻结到位（含所有自动生成的报告文件），先确认「远端是否已有该版本的标签」，再打。
- **反例**：对已存在的标签尝试重指 —— 被规则拒绝即证明该标签不可变，此刻才发现等于返工。

### R13 精准部署前的三方哈希核对
- **现象**：远端可能存在人工校改，本地可能落后；凭记忆列「本次改了哪几个文件」会造成漏传或覆盖（实测以为只有 2 个漂移文件，实际第 3 个同样会被一次全目录部署静默覆盖）。
- **判据**：部署前比对**远端 / 本机工作树 / 版本库 HEAD** 三方哈希，一次性回答「远端有没有人工校改」「本机是否落后」；据此选「只传本次改动」且**不带删除选项**。
- **反例**：先只比本机与远端（少比 HEAD 一方）—— 若仍有差异解释不了，即证明三方缺一不可。

## 类 6 · 探测失败 ≠ 对象不可用（R14–R21）

> 本族共同口径：**探测手段的失败，不能推断被探测对象的状态**。判定「不可用」之前，必须先证明探测手段在该环境下**具备可用性**。

### R14 某些 shell 没有 `/dev/tcp` ⇒ 端口探测恒判 CLOSED
- **现象**：用 `/dev/tcp/host/port` 做端口探测，在该类 shell 下**静默失败、恒判 CLOSED**——据此曾误判「服务全挂」，实际端口一直在正常服务。
- **判据**：端口可达性改用请求工具的返回码（`000` 才是真不通）或系统的监听列表命令；`/dev/tcp` 只写在显式声明 bash 的脚本里。
- **反例**：对一个**确定在监听**的端口跑 `/dev/tcp` 探测 —— 判 CLOSED 即证明探测手段失效，其此前的所有 CLOSED 全部作废。

### R15 进程管理器的列表命令在受限环境里看不到目标服务（假阴性）
- **现象**：轻量列表命令在工具沙箱内**看不到目标服务**，看起来「服务没注册」，实际它跑得好好的；换用**带用户域详情的查询命令**才能看到。
- **判据**：状态查询用能展开用户域的查询形式；顺带注意该环境下的检索不支持某些正则简写，会静默零命中。
- **反例**：先用列表命令查，再用详情查询命令查**同一个**服务 —— 前者空、后者有，即证明列表命令是假阴性来源。

### R16 用前端请求的成败当可达性判据 ⇒ 误报「服务没在跑」
- **现象**：页面加载时先发一个探测请求，不通就弹「服务未运行」；而**探测本身被环境拦截**、新窗口被拦截也弹同一个提示 ⇒ 两类完全不同的故障合并成一个错文案。
- **判据**：**直接尝试打开**，把「打不开」与「服务不在」分开报；探测失败不等于服务不可用。
- **反例**：在探测必定被拦截的环境里跑一次 —— 提示仍是「服务未运行」而服务健康，即证明该判据误报。

### R17 启动应用后需要等待监听就绪
- **现象**：启动本地应用后**立刻**探测端口，连返两个「不通」，判「起不来」；实际约 10 秒后才开始监听。
- **判据**：启动类操作后留出就绪窗口再探测（或轮询到就绪为止），探测一律绕过本地代理直连。
- **反例**：记录「启动时刻」与「首次监听时刻」—— 两者相差数秒即证明「早探 = 失败」是探测时机问题。

### R18 有鉴权的缓存服务不能用 ping 命令探活
- **现象**：对要求认证的实例执行常规 ping，直接返回认证错误 ⇒ 被读成「服务异常」，实际服务正常。
- **判据**：探活降级为**只探 TCP 连通**（建连成功即可）或带认证后再 ping。
- **反例**：分别跑「ping」与「只建连」—— 前者报认证错误、后者成功，即证明失败来自探测方式。

### R19 整个域名临时不可达，而其他域名正常
- **现象**：某域名的 443 全部超时，**DNS 解析正常**，同时其他域名（代码托管、搜索、地图等）全部正常 ⇒ 非全局网络问题、非 DNS 问题；约 40 分钟后自行恢复。连带症状：采集耗时从 10 秒暴涨到 240 秒（逐层重试耗尽），且兜底路径把数据静默写成 0。
- **判据**：先**复测确认是否自愈**，不要急着改代码或换数据源；依赖该域名的脚本必须遵守「空即失败」。
- **反例**：同一时刻对两个域名各发一次请求 —— 只有一个失败即证明是单域故障，不是本机网络。

### R20 「网页打不开」与「接口不可用」不等价
- **现象**：网页超时，据此判「站点整体不可达」；实际接口域名与代码传输通道**全部正常**——受影响的只有浏览器打开网页这一件事。
- **判据**：按**域名分别探**；需要网页侧操作时走移动网络 + 官方入口，镜像站只用于查文档，**禁止在其上登录或建凭据**。
- **反例**：网页失败的同时请求接口域名 —— 返回正常即证明「全不通」的结论过宽。

### R21 「又连不上」常是本地会话态不持久
- **现象**：SSH 报权限拒绝，被读成「通道坏了 / 主机不可达」；真因是**本地凭据代理的会话态在重启或超时后清空**，且没有任何自动加载 ⇒ **每个新会话的第一次连接都必须重新加载**。
- **判据**：连接前统一调一次「确保凭据已加载」的入口（判断依据用**公钥指纹**，不要用会变的注释字段）；加载失败即退出，不带着空会话继续跑分支。
- **反例**：同一会话内连续两次连接 —— 第一次失败、加载后第二次成功，即证明失败在本地会话态而非远端。

## 类 3 · 退出码 0 ≠ 成功（远端侧，R22–R23）

### R22 远端缺少某个 CLI 而错误被重定向吞掉
- **现象**：远端没有该命令行工具，`… 2>/dev/null` 把「命令不存在」的非 0 退出码吞掉 ⇒ 输出为空，看起来像「这个表里没数据」。
- **判据**：远端读结构化数据一律走**解释器内建能力**（`python -c` 之类）而非依赖 CLI；在判定「没数据」之前，先验证工具本身存在。
- **反例**：先跑一次「工具是否存在」的探测 —— 不存在即证明此前所有空结果都是工具缺失，不是数据为空。

### R23 定时任务执行的是绝对路径，可能不在项目目录
- **现象**：项目目录里的脚本被反复记为「未部署的待办」；实际定时条目指向的是**另一个绝对路径**，且线上那份比项目内那份**还新一版**。把项目内那份「部署」过去**也不会被执行**。
- **判据**：先看**定时条目的实际执行路径**，再看两端哈希；差异只在注释或版本说明时，说明它是**快照，不是待部署品**。
- **反例**：改一处只在项目内那份存在的标记，然后等一次周期 —— 线上产物无变化即证明执行的是另一个路径。

## 巡检与口径（R24–R26）

### R24 健康巡检扫日志的三大误报源
- **现象**：① 报告正文 / 分析措辞混入被当成错误关键字；② **计数为 0**（`errors=0` / `failed=0`）命中错误关键字；③ 正常降级（某数据源失败但程序收敛出结果）被当故障。
- **判据**：三层过滤——**只扫程序状态行**（时间戳行 / 标签行 / 异常栈 / 分隔线 / 命令回显）、**剔除零计数片段**、**降级信息不进健康检查**。并明确巡检口径边界：只报「任务有没有跑 + 日志有没有程序级错误」，不报业务与数据质量。
- **反例**：构造一份**只含 `errors=0`** 与一段分析措辞的日志 —— 按你的规则应报 0 个错误；若报出错误，即证伪。

### R25 用「日志相邻行」判远端任务成败
- **现象**：某次运行的确认行在日志里**不见了**，一度判为「失败但报了成功」。真因是**输出缓冲错位**——父进程块缓冲、子进程直写，子进程的确认行被排到父进程该次运行的若干行**之前**（症状 =「本次缺一行、上次多一行」）。所有父子进程混合输出的日志都有此现象。
- **判据**：判据改成**计数**：确认行数 == 全链路完成行数 ⇒ 全部成功；不看某一行在不在。
- **反例**：对同一批日志分别用「找某一行」与「计两种行数」两种方法 —— 前者给出矛盾结论、后者自洽，即证明前者不可用。

### R26 「0 次触发」的二义
- **现象**：某护栏 / 开关连续多批「触发 0 次」，被解读成「今天环境不满足条件」；真因是它的**入参恒为空**（上游一个开关把输入关掉了）⇒ **护栏是死代码**。同类误读：日志里的同名标签命中其实来自**另一个上下文块**，与本次排查的对象无关。
- **判据**：验收任何护栏 / 开关**先证它的输入非空**（一条独立查询），再看触发次数；同名命中还要看它上方数行的**上下文标题**确认来源。
- **反例**：用一条独立查询取该护栏的入参 —— 取到空即证明「0 次触发」的原因是读不到输入，不是条件不满足。

## 类 7 · 执行状态断言无锚可溯（远端侧，R27–R29）

> 与《判据库-本机与工具链》类 7 同源：**断言缺锚即不可验证**，处置一律是降级为**无法判定**。
> 远端侧的特有形态是**锚存在、却指错了地方**——证据是真的，只是它证明的不是你说的那件事。

### R27 观测点与被断言对象不同址
- **现象**：「已部署到服务器」的证据取自**本地**文件；「平台上已是新版」的证据取自**本地**目录。断言的主语在 A、证据在 B ⇒ 锚存在却指向另一个对象。实测形态：本地工作树「干净」被当作发布验收通过——工作树的视角看不见落到仓库外的文件，直到外部访问 404 才暴露。
- **判据**：断言的**主语与观测点必须同址**——说远端就在远端读，说平台包就拉平台包；证据命令里必须出现**被断言对象的标识**（主机名 / 远端路径 / 平台版本号）。
- **反例**：分别取本地与远端同一文件的哈希 —— 两者不等而结论仍写「已部署」，即证明观测点错位。本机可复现：技能目录与其历史快照的 `shasum` 必然不同。

### R28 证据时刻早于被验证动作的时刻
- **现象**：用**动作之前**采集的证据（日志行 / 快照 / 缓存 / 上一次的读数）证明**动作之后**的状态。证据本身「存在且正常」，看起来很有力，但它回答的是「动作前世界是什么样」。实测形态：核对正在被并发改写的资产时沿用十分钟前的读数，结论因此一次失真；正确做法是**写入前重新回读、写完再回读终态**。
- **判据**：先记**动作时刻**，再取**证据时刻**，断言只在**证据时刻 ≥ 动作时刻**时成立；不成立即降级为**无法判定**（≠「失败」）。
- **反例**：对一个文件先取 `mtime`（M1）→ 再写入 → 再取 `mtime`（M2）。M1 < M2，用 M1 证明「写入已发生」应被拒绝；若你的判据仍判通过，即证明时刻锚未纳入考量。

### R29 观测点落在探测手段自身
- **现象**：「接口通了」的证据是**请求工具的退出码**；「服务在跑」的证据是**探测程序打印了 OK**；「配置生效了」的证据是**进程活着 + 无错误日志**。观测点落在探测手段内部，与被探测对象无关。⚠️ 与**第 6 类**互补：第 6 类管「**探测失败 ≠ 对象不可用**」，本条管「**探测成功 ≠ 对象正常**」——两个方向都是把探测手段的状态当成了对象的状态。实测形态：曾以「进程存活 + 日志干净」判「配置已生效」并被界面截图证伪；改读**生效值**（进程实际加载的配置值 / 会话记录里的实际工作目录）后才对上。
- **判据**：探测成功的证据必须是**对象侧的响应内容**（响应体字段 / 业务数据 / 生效值），不是传输层或工具层的成功标志。
- **反例**：对一个**返回 200、响应体却是错误负载**的端点做探测 —— 传输成功、工具报成功、内容与预期格式不符；据此判「接口通了」即证明观测点错位。

## 类 3 续 · 通道相关与聚合失效（远端侧，R30–R32）

> 与《判据库-本机与工具链》L35–L37 同源：**多条通道的「一致」，只有在通道彼此独立时才含信息。**
> 远端侧的特有形态是**观测点看起来分散、实则同一上游**：控制台与接口都读同一份缓存、
> 两个边缘节点命中同一份副本、部署回执与上传输出都来自同一次上传。
> 三条硬约束同本机侧：**独立性自证 / 少数否决 / 标注「一致地错」盲区**。

### R30 远端观测点同源（控制台 / 接口 / 多节点实为同一上游）
- **现象**：「控制台显示已生效」＋「接口返回新版」＋「两个节点都读到新值」——三条通道看起来彼此独立，实际都取自**同一次采集、同一份缓存或同一枚回执**，与远端实体**无关**。⚠️ 与 **R07** 的区别：R07 是**单个字段**走缓存；本条是**多条通道共享同一个上游**，一致因而是**恒真**的，通道再多也不增加信息。
- **判据**：采信远端「多处一致」之前，先确认各通道**不共享上游节点**（不是同一份缓存 / 不是同一次采集 / 不是同一个回执）；**至少一条通道必须直读远端实体**（在远端机器上取哈希，或绕过缓存直取源站）。同源 ⇒ 置信度按**单通道**计，不得写「已交叉验证」。
- **反例**：让两个观测点都读同一份缓存（模拟两个边缘节点命中同一副本）——两者**一致**，而源站已是另一版本，即证明该一致性不含信息；绕过缓存直读源站后分叉出现，才暴露同源。

### R31 多节点 / 多通道取「任一通过」即宣告部署成功
- **现象**：多节点部署的核验写成「任一节点命中即通过」或「取最后一次探测结果」⇒ 未更新的节点被静默放过。实测形态：某次发布核验中一个通道已推成功而另一个通道未并入，只核验先成功的那条会得出「已发布」；且该环境下的查询命令在抖动时会**静默失败**，连失败信号都拿不到 —— 于是「任一通过」连唯一的反对票都收不到。
- **判据**：多节点一律**少数否决**——**任一节点未达标即整体降级**；断言是全称（「全部节点已是新版」）时必须对账**总数**：`达标节点数 == 节点总数`，缺一个即不算完成。还要区分「该节点未更新」与「该节点此刻探不到」——后者是**第 6 类**，须先自证探测手段可用，不得直接读成未更新。
- **反例**：造三个节点产物，其中一个是旧版——「任一命中即通过」的写法**报成功**；把口径换成计数对账（`达标数 2 ≠ 总数 3`）才报失败。两种写法给出相反结论，即证明聚合方式是本次判定的关键变量。

### R32 远端全链路「一致地错」：共同前提未单独校验
- **现象**：所有远端通道**一起错且互相印证**——地址解析把域名指向旧实例，于是「接口通」「页面能开」「健康检查通过」三条通道**一致地**落在旧版上；或共用同一枚已失效凭据 ⇒ 所有通道一致报同一个鉴权错，被读成「对象不可用」（与**第 6 类**同形、方向相反：那边是探测失败被读成对象坏，这边是共同前提错被读成一致通过）。
- **判据**：远端结论必须写明**一致性的来源**与**剩余盲区**；**共同前提本身必须单独验一次**——解析出的地址是不是目标实例、凭据是否在有效期内、是否绕过了缓存、证据时刻是否晚于部署时刻（R28）。共同前提未验或各通道同源 ⇒ 置信度按**单通道**计，不得写「已交叉验证」。
- **反例**：让三条通道都基于同一份解析结果取目标地址——三者**一致**；注入真值（新实例地址）后仍全部给出旧地址，即证明一致性来自共同前提而非事实。单独校验解析结果（与期望地址逐项比对）才暴露。


## 类 7 续 · 证据不可复跑（远端侧，R33–R35）

> 远端侧比本机更容易留下**不可复核**的证据：核验动作与实体之间隔着网络、缓存与回显，
> 「探测到了」与「实体是那个状态」之间的缝隙更宽。本族口径同本机侧的「类 7 续」：
> **证据的价值在于别人能不采信出具方的措辞就复核它**；不可复跑 ⇒ 结论降级，不判失败。
> 落地做法见 `references/方法详解.md` §五。

### R33 远端证据只留回显，不留响应体哈希与读取时刻
- **现象**：远端核验留下的证据是「`curl` 通了 / 状态 200 / 部署回显 ✓」，**没有响应体内容（或其哈希）、没有读取时刻、没有目标实例标识** ⇒ 事后无法判断那次读到的是不是目标实例、是不是缓存副本。与 **R07 / R30** 同源：观测点落在**回显**而不是**实体**，因此它在实体变化后**仍然恒真**。
- **判据**：远端证据必须落到**实体的可比对值**——响应体（或其 sha256）+ 读取时刻 + 目标地址 / 实例标识；只留回显的证据不得作为「已部署 / 已生效」的依据，结论降级为**无法判定**。
- **反例**：对同一个远端响应体造两条通道——一条只读回显（`--cmd "test -f resp.txt && echo READY" --expect-regex "READY"`），一条读响应体哈希（`--cmd "shasum resp.txt"`）；随后把 `resp.txt` 的内容改掉并 `replay --execute` ⇒ 回显通道**复跑仍 PASS**（它验的是文件在不在），哈希通道报「无法判定（哈希漂移）」。两种证据对同一次变化给出相反结果，即证明回显式证据**不可复跑**。

### R34 证据里全是 PASS，没有一条阴性对照
- **现象**：一份证据里每条通道都是 PASS，**没有一条「必然报 FAIL」的对照** ⇒ 无法判断这些 PASS 是检查器有效，还是检查器坏了以后的一律通过。⚠️ 与 **L36 / R31** 方向相反：那边是聚合把 FAIL **吃掉**，这里是**根本没有 FAIL 可吃**。远端尤其常见——探测命令在不通的环境里会**静默失败**，连反对票都收不到（与**第 6 类**同形：探测失败被读成「一切正常」）。
- **判据**：任何要交他人复核或留档的证据，必须至少含一条**阴性对照**（一条必然报 FAIL 的通道）；**缺对照 ⇒ 已证 / 已证伪一律降级为「已执行但未验证」**，不得写成「已证」。
- **反例**：用 `scripts/evidence_pack.py` 建包时只加真检通道、不加 `--control` ⇒ `replay` 报「**已执行但未验证**：缺阴性对照 —— 没有一条『必然报 FAIL』的对照」；补一条对照（查一个必然不存在的串，如 `grep -c v9 <file>`）后，同一份证据转为「已证」。差异只来自**有没有对照**，即证明全 PASS 的证据不足以支撑「已证」。

### R35 证据跨环境沿用未比对指纹
- **现象**：证据包 / 日志 / 结论在 A 环境采集，被拿到 B 环境（另一台机器、另一个用户、另一个 shell、另一套工具集、另一个时区）直接沿用。环境的差异会改变**判读规则本身**（同一条命令在两种 grep 方言下结果相反、同一时刻在两时区下是两个日期、有代理与否决定一次失败是不是假的），沿用者却以为自己在看同一件事。
- **判据**：沿用他人或他机的证据前，先比对环境指纹关键项（`scripts/env_fingerprint.py --diff A.json B.json`）；有关键差异 ⇒ 旧结论**降级为「无法判定」**并在本环境重跑真检；无关键差异也须对锚做一次复读。证据包自带的 `env` 字段可作 A 侧指纹。⚠️ 关键项清单是**通用**的：`wget`、代理变量、凭据代理按**次要项**计——若该证据恰好依赖它们，比对会误判「可比」。处置：**把本证据实际依赖的命令补进关键项再比对**，别只看默认清单。
- **反例**：先存一份本机指纹，再伪造一份改掉 os 与 grep 方言的指纹做比对 —— 比对必须报关键差异并给出 rc=2（不可沿用）。
- **反例准备**：`python3 {skill}/scripts/env_fingerprint.py --save {tmp}/a.json && python3 -c "import json;d=json.load(open('{tmp}/a.json'));d['os']='OtherOS';d['grep_bre_alternation']='true' if d.get('grep_bre_alternation')=='false' else 'false';json.dump(d,open('{tmp}/b.json','w'))"`
- **反例命令**：`python3 {skill}/scripts/env_fingerprint.py --diff {tmp}/a.json {tmp}/b.json`
- **反例判据**：`rc:2`
- **来源**：一次真实比对：把两份环境指纹的平台与检索工具方言改掉后，比对报 3 项关键差异、退出码 2 ⇒ 判「不可直接沿用」；同一份证据在 A 机器采集、拿到 B 机器用（shell / grep 方言 / 工具集 / 时区 / 代理设置不同）时，判读规则会整体翻转
