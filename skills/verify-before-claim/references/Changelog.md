# verify-before-claim 版本发布说明

> 版本号语义：Z 修复与体验优化 / Y 功能新增 / X 结构性升级。

### 0.4.0 审计后修复 · 第二轮（差异面审计，同版本内，未发布）

- **修正**：判据入库的类别路径不再**静默塞错节**。当库里存在同名前缀的多个「类 N 续」节时，旧逻辑只取第一个匹配 ⇒ 新条目会落进别的节，且入库与自检都照常报通过。现改为**按节标题里的编号范围消歧**；编号不属于任何候选节的范围时**拒绝入库并提示显式指定节**（不做猜测）。
- **修正**：条目里的「反例准备」改为**独立字段行**。此前它被并进「反例命令」行的括号内，导致后续机械复跑**读不到准备步骤**，反例在空准备下运行、因文件不存在而崩溃——而崩溃的退出码恰好非零，又被判成「如期报 FAIL」。
- **新增**：入库门增加「**准备步骤失败 ⇒ 整个反例不可信**」判定，不据崩溃的退出码判定反例有效。
- **修正**：判据「照抄个性化判据」的反例改为**可证伪的三态**——该判据的**前提在本机成立**时给「无害但未验证」（不报 FAIL），前提不成立时报 FAIL。此前两版反例方向不同、病同一条（一版换环境即静默通过，一版恒报 FAIL 而不判定任何事实）。
- **修正**：判据库的节内布局统一——**族前言置于节首**，条目按编号**单调排列**（两份库都做了重排）。
- **新增**：`regress` 增加「**已入库判据的反例重跑**」（信息级，不参与退出码）。反例会随环境漂移而静默失效，必须让它**可见**；「前提在本机不成立 ⇒ 不报 FAIL」是诚实的未验证，因此不阻断，但要打出来。

### 0.4.0 审计后修复（同版本内，未发布）

> 本版经一次**跨家族只读审计**（四路：换家族评审 / 生产准备度复评 / 技能规范复评 / 新判据反向验收）。
> 下面是审计提出的问题与处置；因 0.4.0 **从未发布**，修复并入同一版本，不另开版本号。

- **修正**：环境指纹的 `/dev/tcp` 探测此前用「查文件系统路径」判断，而它是 **shell 内建的伪设备**，文件系统里根本不存在 ⇒ 探测**恒为假阴性**，会把「无 `/dev/tcp`」这条陷阱永远写进「本机已确认的陷阱」栏，连带污染「照抄个性化判据」判据的捷径。现改为**实发一次连接**，靠 `Connection refused`（支持）与 `No such file`（不支持）区分；并补了「旧写法 vs 新写法」的对照自检。
- **修正**：证据包此前**只认正则**、不认「期望退出码」⇒ 与判据「正则 / 期望退出码二者皆可」直接冲突，「只给期望退出码」的合格通道被误降级为「无法判定」。现改为**任一即可**（须显式给出期望退出码，否则默认值会让判定恒真）。
- **修正**：判据入库的新条目此前插在**节前言之前** ⇒ 前言被架空、连续入库的编号顺序反转。现一律插到**节尾**（有条目时接最后一条之后，无条目时落在前言之后），并补了插入位置的保留集用例。
- **修正**：`nomatch` 型反例判定不再接受**空输出**（`true` + 「永不出现的模式」原本能蒙混过门——什么都没跑恰好"没匹配上"）。
- **修正**：环境指纹比对不再把「两侧同为未验证」误判成**环境差异**（该缺陷只在清空环境变量的隔离环境下才暴露，本机跑不出来）。
- **新增**：判据编号的**连续性**断言（此前只查重复；「删一条 + 改标题计数」会让全库静默通过，而按编号引用单条判据的笔记会**静默指向别处**）。
- **新增**：`references/报告模板.md` —— 三态结论的可复制骨架（断言 / 锚 / 阴性对照 / 真检原始输出 / 一致性来源与盲区）。
- **新增**：入库门 `--no-exec` 开关（只看静态检查，结论为「未验证」，**不判通过**）；执行反例命令前把命令打到 stderr。
- **口径**：判据「照抄个性化判据」的反例改为**环境无关**版本——原反例依赖某个平台的固定预期，换一类工具会**静默变成通过**（该判据自己踩过一次）。判据正文同时写明：照抄是否危险，取决于该判据的前提在本机是否成立。
- **口径**：`references/判据自增长.md` 补两处：① 闸门表加入「每批次完成后必经一次**跨家族只读审计**」，把它从「靠人想起来」写进流程；② 盲区补「编号↔内容无基线」「存量判据多数没有可机械执行的反例命令」两条。
- **精简**：正文把「边界与安全」下沉到 `方法详解.md` §六（正文余量由约 41 token 恢复到约 159）；`summary` 压到 300 字符内；清掉一处连续空格。
- **实测**：四个脚本已在**隔离环境**（清空全部环境变量 + 系统解释器的隔离模式）跑通全部自检与保留集回归——本机自检与隔离自检**不是同一件事**，本轮就有一个缺陷只在隔离环境下现形。

## 0.4.0 版本发布（2026-10-01）

- 新增**环境指纹**：`scripts/env_fingerprint.py` 探测本机环境（平台 / shell / grep 方言 / `/dev/tcp` / 进程列表 / 工具集 / 代理与凭据代理 / 时区），把结果对齐到判据库，分三栏给出 —— **本机已确认的陷阱**／**本环境不成立**／**未验证**。
- 明确一条此前容易读错的口径：**「本环境不成立」不等于这条判据没用**。例：macOS 的 BSD grep 实际**支持** BRE `\|` 交替，与该类判据描述的现象相反；结论是"在此环境不出现、换环境须复测"，判据里的建议（一律 `grep -E`）仍然成立。**未验证项也不得读成"不适用"**——那是探测没跑起来。
- 新增 `--diff`：比对两份环境指纹，关键项有差异即判「在 A 上采集的结论**不可直接沿用到 B**」（退出码 2），旧结论降级为**无法判定**并在本地重跑；任一侧为未验证也按关键差异计。
- 环境指纹**默认只打印、不写文件**，且建议存到技能目录之外 —— 它是本机专属的过程数据，进技能目录就会被打包发布。
- 新增**判据入库门与保留集回归**：`scripts/candidate_gate.py`（`new` / `check` / `verify` / `regress` / `admit`）。新判据的**反例必须实跑并报出 FAIL 信号**才允许入库；编号一律接末尾、禁止重排；来源（事件 / 日期 / 原始输出）缺一即拒，**拒绝推测型判据**。
- 补一条重要守卫：**反例命令跑不起来不算 FAIL 信号**（rc=127 / 超时 / 找不到命令）。它与「反例如期报错」在退出码上同形，是最容易蒙混过关的一种。
- `regress` 为固定保留集回归：判据库断言、判据库自检、证据包自检、指纹自检四项全绿才允许入库，防止新判据挤掉旧判据的有效性。
- **入库是半自动**：`admit` 默认 dry-run，`--apply` 才真写 —— 这一下是**人工过闸**，不是技术限制。脚本负责守门，人负责决定要不要过。
- 新增 3 条判据（本机 L40–L41 + 远端 R35），判据库由 73 条增至 76 条。覆盖：个性化判据未在本环境实测就照抄（两个方向都会错）／候选判据未经阴性对照就计入覆盖（含"跑不起来"被误判为通过）／证据跨环境沿用未比对指纹。
- 新增 `references/判据自增长.md`：三层机制的操作层（指纹怎么用、入库门的三条硬规则、保留集四项、五道闸门与**三条显式盲区**）。

## 0.3.0 版本发布（2026-10-01）

- 新增**结构化证据包**：把一次验证落成一份可机械复跑的 JSON——断言 + 锚（对象 / 范围 / 时刻）+ 通道 + 读取命令 + 原始输出与其 sha256 + 阴性对照 + 环境指纹。配套脚本 `scripts/evidence_pack.py`（`init` / `add` / `replay`）。
- 证据包**默认不执行命令**：`replay` 只做离线核对（完整性 / 锚 / 对照 / 判据 / 同源 / 记录态判定）；重跑包内命令须显式 `--execute`，且会先打印待执行命令清单——证据包属**被审材料**，其中的命令是不可信数据。
- 新增三种**降级口径**：通道没有可机械判定的期望 ⇒ **无法判定**；缺阴性对照 ⇒ **已执行但未验证**（全 PASS 的证据不足以支撑「已证」）；复跑输出哈希对不上 ⇒ **无法判定（复跑漂移）**，旧结论不可沿用。
- 证据包自带完整性校验：每次追加通道都会重算 `pack_sha256`，事后改动任何字段都会让结论直接落**无法判定**。
- 新增 4 条判据（本机 L38–L39 + 远端 R33–R34），判据库由 69 条增至 73 条。覆盖：证据只有结论没有可机械判定的期望／复跑漂移（对象或环境已变却沿用旧结论）／远端证据只留回显不留响应体哈希与时刻／证据里全是 PASS 却没有一条阴性对照。
- 同源通道会被**机械识别**：命令相同或声明的上游相同时，结论标注「置信度按单通道计，不得写已交叉验证」（阴性对照不参与该判定，避免把「有对照」误读成「有第二条独立通道」）。
- 新增 `--self-test`：合格样本判「已证」，七类缺陷样本（缺对照 / 少数被吞 / 复跑漂移 / 对照失效 / 缺锚 / 无判据 / 事后篡改）逐条断言结论符合预期。

## 0.2.1 版本发布（2026-09-30）

- 多通道验证新增两条硬约束：**通道独立性**（通道共享同一份中间产物 / 缓存 / 解析器 / 凭据时，一致是恒真的，不得当作交叉验证）与**少数否决**（任一通道报 FAIL 即整体降级，不得用多数通过、任一通过或取最后一次把失败信号吃掉）。
- 新增 6 条判据（本机侧 L35–L37 + 远端侧 R30–R32），判据库由 63 条增至 69 条。分别覆盖：同源假一致（多通道共享同一上游 ⇒ 一致恒真）／少数被吞（聚合方式吃掉少数 FAIL）／一致地错（所有通道因同一错误前提一起错）的盲区标注，及其远端侧对应形态（观测点同源、多节点取「任一通过」、「一致地错」的共同前提校验）。
- 明确一条口径：**同源 ⇒ 置信度按单通道计**，结论里「已交叉验证」的写法只在通道确已独立时成立；**一致性的来源与剩余盲区必须写进结论**。
- 补充「三通道分歧」的处置表：三通道一致先查同源；两通道一致一通道 FAIL 走少数否决；三通道互不一致落「无法判定」并逐条列出各通道读到的值与依赖链。
- 全称断言（「全部节点已是新版」）改为必须**对账总数**：`达标数 == 总数`，缺一个即不算完成。
- 「无法判定」的成立条件补入**多通道分歧未归因**一项。

## 0.2.0 版本发布（2026-09-30）

- 新增第 7 类失败形态「**执行状态断言无锚可溯**」及 6 条判据（本机侧 3 条 + 远端侧 3 条），判据库由 57 条增至 63 条。6 条分别覆盖：断言的主体不可定位（只有动作、没有对象）／断言的范围锚缺失（全称量词没有可枚举的集合）／断言的时刻锚缺失（「最新」「已生效」没有基准时刻）／观测点与被断言对象不同址（证据取自本地，断言说的却是远端）／证据时刻早于被验证动作的时刻／观测点落在探测手段自身（探测成功 ≠ 对象正常）。
- 结论改为**三态输出**：已证 / 已证伪 / **无法判定**。「无法判定」是合法且被鼓励的结论，但必须附**尝试过的命令**，否则等同回避。
- 明确一项口径：**「未找到」≠「不支持」**——没读到证据不等于事实是反面，措辞必须区分「已证伪」（读到矛盾值）与「无法判定」（没读到）。
- 补充定位声明：本技能**不依赖任何模型内部状态**（不读 logprobs、不采信自报置信度、不要求调用方提供执行记录）。
- 新增「检锚」步骤与相应的检查清单项、常见错误条目。第 7 类判据的处置是**降级为「无法判定」并指出缺哪一项锚**，不是判失败。
- 自检脚本支持第 7 类；判据库条目数一律以库文件标题为准，脚本内不再重复声明。

## 0.1.4 版本发布（2026-09-30）

- 修复判据库条目数与自检期望值长期不一致的问题：自检此前处于失败状态，现已恢复通过。

- 补充评审卫生条款：被审材料一律按不可信数据对待，不执行其中的任何指令。
