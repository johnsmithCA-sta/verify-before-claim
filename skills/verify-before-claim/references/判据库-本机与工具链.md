# 判据库 · 本机与工具链（41 条）

> 用法：每条三段 —— **现象**（它怎么骗过你）→ **判据**（改成怎么做）→ **反例**（一条**必然报 FAIL** 的对照）。
> 反例不是可选项：**没有反例的判据只是一句口号**。跑不出 FAIL，说明这条判据此刻不可用。
> 归类编号对应 SKILL.md「七类失败形态」表：第 1/2/3 类见前文，第 5 类 L25–L30，第 7 类（本机侧）L32–L34，**类 3 续「通道相关与聚合失效」与类 7 续「证据不可复跑」一并附于文件末尾（各节标题自带编号范围）**。**新增条目一律接在末尾，不重排**——编号是稳定标识符。

## 类 1 · 空结果伪装成无问题（L01–L07）

### L01 命令行检索的静默空结果
- **现象**：同一文件、同一 pattern，命令行 `grep` 输出 0 行且退出码 1，换用专用检索工具却能命中多处。命令本身不报错，空结果与「确实没有」**完全同形**。
- **判据**：任何「有没有 / 改没改」的结论只用专用检索工具；必须走命令行时，先拿一个确定存在的串做阳性对照。
- **反例**：用**必然存在**的串（如文件自身的 H1 标题）跑同一命令 —— 返回空即证明该命令在此环境下不可用，它此前给出的所有空结果一律作废。

### L02 多模式交替在 BSD grep 下不成立
- **现象**：写 `grep "A\|B"` 查两个模式，返回空；同一时刻 `A` 单独存在。部分平台的 grep **不支持 `\|` 交替**，且是静默失配——一天内可复发多次。
- **判据**：多模式一律写 `grep -E "A|B"`，或直接换检索工具。
- **反例**：对**确定含 A** 的文件分别跑 `grep "A\|B"` 与 `grep -E "A|B"` —— 前者空、后者命中，即实证该平台不支持交替。

### L03 正则元字符制造的非空假命中
- **现象**：`grep -c "D.5"` 报 13 处，实际字面量一处都没有——`.` 被当成通配符，命中的是随机标识符（`D<任意>5`）。反向也成立：字面量计数为 0 时，正则计数仍能给出「有」。
- **判据**：统计字面串出现次数用**非正则**手段（精确子串计数）；必须用正则时，先把元字符转义。
- **反例**：构造一个「只有 `D` 与 `5` 被随机字符隔开、无字面 `D.5`」的样本，正则计数应 >0 而字面计数应 =0 —— 两者不等即证明正则计数不可用于此结论。

### L04 复合命令的内层引号被吃掉
- **现象**：`ssh host "… | grep -c 'x'"` 返回 `0`，据此判「远端没有这个能力」；把同一条改成外层单引号重跑，功能其实正常。内层引号在多层 shell 解析中被消费掉了。
- **判据**：跨机执行的判定命令，外层用单引号包整串（内部自由用双引号）；**结论性质的判定不依赖一次复合命令**，重跑一遍干净写法再下结论。
- **反例**：同一条判定分别用两种引号写法跑 —— 两次结论不一致即证明其中一次是解析产物，不是事实。

### L05 截断式计数（`head` 把 20 看成 2）
- **现象**：`find … | head -25` 数文件数，把对方的 20 个脚本误看成 2 个，直接导致「差异点」结论出错。
- **判据**：计数一律全量（`wc -l` / `sort -u | wc -l`），不用 `head` 截断；展示时截断、计数时不截断。
- **反例**：同一次命令分别跑「带 `head -N`」与「不带 `head`」两版 —— 计数不同即证明截断版不可用于计数。

### L06 范围过滤两侧格式不统一 ⇒ 排除 0 条
- **现象**：给脚本加 `--since 2026-09-14`，但文件名里的日期是 `20260825`。字符串比较下 `"20260825" < "2026-09-14"` 恒为 False ⇒ **一条都没排除、且不报错**，样本仍是全历史。只看「退出码 0 + 报告已写出」会当成成功。
- **判据**：按日期 / 编号 / 版本做范围筛选，两侧先归一化（去掉分隔符）再比；**并把「排除了 N 条」打进日志**——有计数才可能发现 N=0。
- **反例**：加过滤参数前后各跑一次，比较样本量 —— **一模一样**即为失败信号（先怀疑格式不匹配，不要怀疑数据源）。

### L07 空即失败：兜底路径的空集合必须带错误标记
- **现象**：采集 / 查询的兜底分支返回空列表却不带错误字段，绕过失败校验被写成 0，历史里就多了一条「真的没有」。
- **判据**：账号 / 池 / 目录下**必然有 N 条**的场景，返回空集合**一律判失败**并显式标记错误；兜底路径最容易漏标记，而它恰好只在主路径已失败时才走。
- **反例**：用一个**必然非空**的标识跑同一采集路径 —— 返回空即证明链路的「空」不代表「没有」。

## 类 2 · 成功回显 ≠ 落盘（L08–L15）

### L08 编辑器工具回报成功但未落盘
- **现象**：批量编辑里个别条目标 success，却在文件中查不到（实测约 2/12 次），重新编辑才生效。
- **判据**：改完**立即用另一条读取路径回读特征串**，不信工具返回的状态；一条改动对应一次回读。
- **反例**：回读一个**故意写错**的特征串 —— 它必须读不到。若连错串都「读到」，说明回读的手段本身失效。

### L09 同文件的并行改动竞态
- **现象**：同一条消息里并发发两个改动，两边都报成功，后写者覆盖先写者；**是常态，不是偶发**。
- **判据**：同文件上「读—改—写」必须串行；改完逐条回读，回读命中数应等于改动条数。
- **反例**：改 3 处后回读 4 个特征串（3 个真 + 1 个假）—— 真串应 3/3 命中、假串应 0 命中；若 4/4 全中，回读无效。

### L10 平台命令回显 ✓ ≠ 生效
- **现象**：给仓库加标签 / 改设置类命令回显打勾，实际属性没变；命令成功只说明请求被受理。
- **判据**：改完**用读接口回读该属性**并与目标值逐项比对，不看命令回显。
- **反例**：回读一个**从没设置过**的属性名 —— 应返回空 / 缺省值。若它也返回「已设置」，说明回读接口不可信。

### L11 工作目录漂移把文件写到别处
- **现象**：前一条命令 `cd` 到某目录，后一条用相对路径复制文件 ⇒ 文件落到错误位置；**本机检索与远端列目录双处都看不见**，直到外部访问 404 才暴露。
- **判据**：跨目录写文件一律用绝对路径；写入后立即 `pwd && ls -la <绝对路径>` 双确认。
- **反例**：用一个**故意不存在**的相对路径做同样的复制 —— 应当失败或落到非预期位置；若它「看起来成功」而你复不出落点，说明你在靠猜。

### L12 用错方法名被读成权限不足
- **现象**：更新某类配置项用 `PATCH` 返回 `404 Not Found`，极易被读成「token 权限不够」而绕远路。
- **判据**：先查该接口的**正确方法**（有些只接受整体替换式 `PUT`）；改完回读生效值。
- **反例**：用故意错的资源标识跑同一方法 —— 应返回与「方法错误」**不同**的状态码，据此区分「路径错」与「方法错」。

### L13 改了受管脚本 ≠ 生效（需重启）
- **现象**：服务由进程管理器托管，改了脚本文件但没重启进程 ⇒ 新代码从未加载；只改静态资源则不用重启。**白改**且无任何报错。
- **判据**：区分「需要重启的改动」与「读盘即生效的改动」；重启走**原地重启**通道（不注销注册），重启后核进程启动时间晚于文件修改时间。
- **反例**：改一处只在**新代码**里存在的输出串 —— 未重启时应**查不到**；若未重启也查得到，说明改动其实不用重启（或你的核验点选错了）。

### L14 整文件重写盖掉并发写者
- **现象**：基于几分钟前的读取结果做整文件重写，期间另一个写者做了增量修改 ⇒ 对方的更新被静默抹掉，**两边都以为成功**。
- **判据**：优先增量修改，慎用整文件覆盖；确需重写**先重读**当基线；写入前看文件 mtime——晚于你上次写入且内容有陌生变化 ⇒ 有并发写者，**先报告后动手**。
- **反例**：写入前记录一次 mtime，与上次写入时刻比较；若中间存在第三方写入窗口而你仍全量重写，就会复现丢更新。

### L15 改写产物 ≠ 已发布（平台受理的是提交那一刻的包）
- **现象**：改完文件就算「已上线」，但平台侧仍是提交审核那一刻的版本；提交后本地继续改**不会自动同步**。核验时只看「能搜到该名称」会漏。
- **判据**：判「已上架」要比对**内容**：拉平台包 → 逐文件哈希 + 字节数 + 章节结构三方比对。
- **反例**：拿一个**刚新增、尚未提交**的章节标题去平台包里搜 —— 应查不到。查得到说明你比对的是本地，不是线上。

## 类 3 · 退出码 0 ≠ 成功（L16–L24）

### L16 框架层的错误退出默认写成 0
- **现象**：某类工具箱的错误处理函数签名是 `error_exit(message, code=0)` —— **默认退出码就是 0**，鉴权 / 接口失败只体现在标准输出里的错误字段。只看退出码的调用方会把失败读成成功（实测：报「成功」+ rc=0，目标一行未写）。
- **判据**：判错**必须解析输出体**中的错误字段，不用 `returncode`。
- **反例**：用**故意无效的凭据**跑一次写入 —— 退出码很可能仍是 0；若你的校验仍报成功，即证明校验点选错了。

### L17 空集合的全称判断恒真
- **现象**：`ok = all(x.get("success") for x in res)` 在 `res == []` 时恒为 True ⇒「什么都没写」也报成功。
- **判据**：**空结果必须判失败**；提交 N 条就断言返回记录数 == N，逐条 success。
- **反例**：对**空集合**跑同一判断 —— 它返回 True 即证明该判断不能用来判成败。

### L18 传输命令 rc=0 但目标不落地
- **现象**：文件传输命令返回 rc=0，目标端目录存在、也不报错，但**文件根本没落地**。⚠️ **先排除误用签名，再怀疑通道**：`scp` 的某个参数漏了 `host:` 前缀时，该路径被当成**本地路径** ⇒ 命令退化成一次本机→本机的拷贝，rc=0、目标端当然读不到文件。（2026-09-23 实测复现；同一现象在 09-10 被归因为「scp 通道不可靠」，导致整条部署线弃用 scp。）
- **判据**：① 先核对**至少一个非选项参数含 `host:`**，再谈通道；② 传完**在目标端**读哈希——不看 rc、不看源端、不看「命令没报错」；③ 通道确不可靠时才改用 stdin 管道直写。
- **反例**：故意漏掉 `host:` 跑一次 —— 若「目标端读不到」照样触发、而你把它记成通道故障，即证明必须先做参数核对；再补上 `host:` 重跑，文件落地即完成归因。

### L19 shell 不做未引号变量的词分割
- **现象**：`FILES="a b c"; for f in $FILES; …` 在某类 shell 下**只迭代一次**（整串当单个文件名）⇒ 循环体静默未执行：批量操作没发生、后续命令报「文件不存在」，而命令本身 rc=0。
- **判据**：用数组 `FILES=(a b c)` 或逐个写死；循环体内加计数器，断言计数 == 元素数。
- **反例**：在循环体里累加计数并打印 —— 期望 3 而实际 1，即证伪。注意**同一段循环跨机可能表现不同**（另一侧 shell 词分割正常），别读成「服务器行为不一致」。

### L20 读无换行结尾的流 + 遇错即退 ⇒ 静默中断
- **现象**：脚本用 `IFS= read -r VAR` 读标准输入，而输入流**末尾没有换行** ⇒ read 返回非零 ⇒ 在 `set -e` 下静默中断，不报错，看着像「没执行」。
- **判据**：喂脚本的流**末尾显式补一个换行**；或改用能容忍无换行结尾的读取方式。
- **反例**：分别喂「带末尾换行」与「不带末尾换行」两份等价输入 —— 两者行为不一致即定位到本判据。

### L21 解析工具输出前未剥颜色码
- **现象**：门禁 / 检查器输出带 ANSI 颜色转义，直接正则匹配**必静默失配**——PASS 与 WARN 一项都读不到，统计出「零问题」。
- **判据**：解析前先剥转义序列，再匹配；并用已知结果对账。
- **反例**：拿一段**已知含失败项**的输出跑同一解析器 —— 必须报出该失败项。报不出即证明解析器失效，其此前的「零问题」全部作废。

### L22 外部命令被中断 ≠ 没执行
- **现象**：命令返回网络错误或被中断，看起来「没跑成」；服务端其实**已落库**。据此重跑会撞版本 / 产生重复。
- **判据**：重发前先**查服务端状态**（版本号 / 时间戳 / 已发布文件哈希）与本地比对，再决定「重发」还是「收工」。
- **反例**：先查一次终态基线，再制造一次中断调用，复读终态 —— 终态若已变，即证明「中断 = 未执行」是错的。

### L23 严格模式下告警也算失败
- **现象**：统计失败项时只数 `✗` 行，漏掉 `⚠ [告警]` 行 ⇒ 明明 `--strict` 判了失败，你的汇总却是 0。
- **判据**：严格模式下的失败统计必须**同时**取错误行与告警行，并与总行数对账。
- **反例**：构造一份**只含告警、不含错误**的输出，用你的统计逻辑跑 —— 应报失败；报 0 即证明统计口径漏了一类。

### L24 校验脚本自带写副作用
- **现象**：某个「验收」脚本会**重写基线文件**。跑在「同步 → 门禁 → 打包 → 发布」链路中间，会出现**打包内容 ≠ 提交内容**（两端拿到不同版本的同一文件，判定值却相同）。
- **判据**：带写副作用的校验脚本，先把目标目录复制到临时目录再跑，或把它排到打包 / 提交**之前**。
- **反例**：跑一次后比对基线的哈希 —— 变了即证明它是写操作，不是只读校验。

## 类 3 续 · 只读模式下的写盘自检恒真（L31）

### L31 零写入（dry-run）模式下，越界 / 落盘类自检恒报 PASS
- **现象**：流水线的自检行里有一行是「产物是否越出受保护区」——取写入集合逐个判前缀。而在 **`--dry-run`（零写入）** 模式下该集合是**空集**，判据**恒为 0 / PASS**：看起来「写盘路径已验证」，实际**根本没写过任何文件**。（2026-09-27 实测：同一脚本 `--dry-run` 与真跑输出**逐字相同**的自检行。）
- **判据**：写盘类自检必须**同时断言非空**（`written > 0` 且全部在根内），并把模式写进输出行（`mode=dry-run|commit`）；**只读模式下的 PASS 一律降级标注为「未验证」**，不得作为落盘依据。真验证需一次**非零写入采样**（哪怕只写 1 个对象）。
- **反例**：同一脚本先跑 `--dry-run`、再跑真跑 —— 两次自检行若**逐字相同**，即证明该判据在只读模式下不可用；补上 `written=N>0` 断言后，dry-run 应报「未验证 / 跳过」而非 PASS。

## 类 5 · 元数据 ≠ 实体（本机侧，L25–L30）

### L25 批量取哈希的输出顺序错位
- **现象**：批量取多个文件的哈希，输出顺序与参数顺序错位 ⇒ **引用哈希时张冠李戴**（把 A 的值记成 B 的），据此做出的「一致 / 不一致」判断全错。
- **判据**：引用哈希前先确认「这个值到底是谁的」；逐个单文件取，或批量后逐行对齐文件名再取用。
- **反例**：对**两个内容必然不同**的文件逐个取哈希，再批量取一次 —— 两边逐行比对，错位一次即暴露。

### L26 哈希不一致 ≠ 内容不同
- **现象**：同一份逻辑内容因**写入方式不同**带 / 不带尾部换行，字节数差 1，直接比对会误判「值变了」。两种相反的错误都会发生：误删唯一真值，或把冗余副本当独苗留下。
- **判据**：判等同**先归一化**（去空白 / 统一行尾）再比；比对结论要能复现两次。
- **反例**：构造两份只差尾部换行的等价样本 —— 归一化后应判等同；若归一化前后结论相反且你能复现，说明确实踩到了本判据。

### L27 新鲜度窗口与任务周期不同频
- **现象**：健康巡检按 30h / 76h / 192h 判「文件未更新」，而某个任务本身就是**季度周期**（约 2160h）⇒ 必然误报「没更新」，多次之后告警被无视。
- **判据**：判「跑没跑」的窗口必须与**任务自身周期**同频；跨周期的任务要么单独判定，要么由它自己的告警通道兜底。
- **反例**：拿一个**周期远长于窗口**的任务跑同一巡检 —— 它报「未更新」即证明窗口选错（不是任务没跑）。

### L28 工作树干净 ≠ 没有落错位置的文件
- **现象**：版本管理的状态检查「无未跟踪变更」只说明**在当前工作目录视角下**没有残留；落到别处的文件它看不见（实测直到匿名访问 404 才暴露）。
- **判据**：发布 / 部署验收必须查**远端实际内容**（远端树），本地提交干净只是必要条件。
- **反例**：故意把一个文件写到仓库外，再跑本地状态检查 —— 仍是干净；据此可证伪「干净 = 没问题」。

### L29 「已删除」的措辞必须与事实对齐
- **现象**：删除动作会被应用层重定向到回收站——原位置确实清空，但**空间不释放**；对回收站内部的再次删除会被显式拒绝。说「已删除」并暗示空间已回收是错的。
- **判据**：措辞用「已移入回收站」，并告知释放空间需要用户侧手动清空；对**已经不在回收站**的东西，不要记成自己删的。
- **反例**：删除前后各看一次可用空间 —— 未减少即证明「删除 ≠ 释放」。

### L30 判签名用对象原始头，不用验签命令的输出
- **现象**：某版本控制系统在缺少信任配置时，验签命令对**已签名**的对象输出「无签名」；直接检索签名头也会漏（标签对象的签名格式与提交对象**不同**）。
- **判据**：判「有没有签名」看**对象原始内容的头部**，并区分提交对象与标签对象两种写法；跨类型套用同一检索方式会得到假阴性。
- **反例**：对一个**确定已签名**的对象跑你的判定 —— 报「无签名」即证明判定方式错；再对它跑一次确定未签名的对象，两次结果应能区分。

## 类 7 · 执行状态断言无锚可溯（L32–L34）

> 本族口径：**断言要能被验，先得能被指。** 一条断言只有同时给出「**可定位的对象标识**」与「**能读出该对象状态的命令**」，才算**有锚**；缺锚的断言既不成立也不失败，它的正确处置是**无法判定**。
> 与前六类的区别：前六类是**有锚但锚被误读**（假成功）；本族是**锚不存在**——验证动作根本无从下手。
> 本族判据的处置**不是**「判失败」，而是**降级为「无法判定」并给出补锚要求**（见 SKILL.md「三态输出」）。

### L32 断言的主体不可定位（「我已经检查过了」）
- **现象**：结论的主语是**自己的动作**，不是**对象的属性**。「我已确认」「我核对过了」「检查完毕」——这类句子没有说出任何关于世界的话，因此**既不能证实也不能证伪**：别人无法复跑，因为它没指向任何可读对象。实测形态：把「进程存活 + 日志无错误」当成「配置已生效」的证据——证据挂在**探测手段**上，断言的措辞却是**对象**的状态，随后被界面截图直接证伪。
- **判据**：断言必须能改写成「**对象 + 属性 + 值**」。写不出对象标识（路径 / 主机 / URL / 记录 ID）时，该断言一律降级为**无法判定**，**不得**用「已确认」收尾。
- **反例**：拿「我已经检查过了」去构造一条读取命令 —— **构造不出**（无对象可指）；对照「远端 `/root/x/state.json` 的 `mtime` 晚于 `T`」，同一手段能构造出 `ssh host 'stat -c %Y /root/x/state.json'`。两句若给出同样结论，说明你的判断没有在看「锚」。

### L33 断言的范围锚缺失（「都改完了」）
- **现象**：全称量词（都 / 全部 / 所有 / 每一个）没有配**可枚举的集合**——断言的强度远超证据的强度：说「全部」而只读了其中最显眼的一个。实测形态：任务台账里批量写「全部完成」，而该信号在原始来源上**连续多日为 0**（同一日志里 10 天没有一条完成行）；全称断言底下没有任何可对账的枚举。
- **判据**：全称断言必须给出**集合的生成方式**（一条能列出成员的命令）或**显式枚举**；两者都缺时降级为**无法判定**，不得以「都」字通过。
- **反例**：对「全部改完了」执行 —— 没有可传参的集合，计数命令**构造不出**；对照「快照目录 `backups/<name>-<ts>/` 下的所有文件」，同一手段能跑出 `find … -type f | wc -l`（实测 8）。前者产出不了计数，即证明范围锚缺失可被识别。

### L34 断言的时刻锚缺失（「已是最新」）
- **现象**：「最新 / 现在 / 已生效 / 当前是好的」没有**基准时刻**。同一条命令在不同时刻会给出不同答案，而断言里没有记录读取时刻 ⇒ 事后无法区分「**状态变了**」与「**当初就判错了**」。实测形态：把对账 / 评审产生的**某一刻快照**当成**执行终态**引用——快照只回答「取证那一刻世界是什么样」，回答不了「现在是什么样」。
- **判据**：凡断言含「最新 / 已生效 / 现在是」，必须带**读取时刻 + 比较基准**（「T1 读 A = v1；同一时刻读 B = v1」）；缺时刻的断言不可复现，降级为**无法判定**。
- **反例**：对同一对象在间隔后读两次 —— 若值不同而断言只有一个「最新」，就无法区分状态变更与当初误判。可跑：取一次 `mtime` → 写入 → 再取一次，两次不等即证伪「无时刻锚的『最新』可复现」。

## 类 3 续 · 通道相关与聚合失效（L35–L37、L41）

> 本族口径：**多条通道的「一致」，只有在通道彼此独立时才含信息。**
> L17（空集合的全称判断恒真）与 L31（只读模式下写盘自检恒真）都是**单通道恒真**；
> 本族是**多通道恒真或恒通过**——信号更多了，信息量却一点没增加，因此比单通道更难发现。
> 三条硬约束：① **通道独立性**未自证 ⇒ 一致性不作证据；② 聚合一律**少数否决**；
> ③ 结论必须显式标注**「一致地错」盲区**。做法与聚合规则见 `references/方法详解.md` §一。

### L35 同源假一致（多通道共享同一上游 ⇒ 一致恒真）
- **现象**：两条「独立」通道其实读的是同一个底层信号——同一份中间产物、同一个缓存、同一个解析器、同一枚凭据、同一时刻的同一份快照。它们的输出**结构性相关**，一致是**必然**，不是交叉验证的结果。用这种一致性当证据，等于把同一个数除以自己，再宣称「两处对上了」。典型形态：报告生成链路里两个校验通道都读同一份已生成的报告文件，而报告由上游脚本写出——上游静默失败时，两通道一致地给出旧值且互相印证。
- **判据**：采信「多通道一致」之前，先列出每条通道的**依赖链**（它读哪个对象、经不经缓存、用哪个解析器），确认任意两条**不共享上游节点**；共享 ⇒ 该一致性不得作为证据、置信度按**单通道**计，并补一条**直读实体**的通道（绕过中间产物与缓存）。
- **反例**：让两条通道都从同一份中间文件读数（shell 计数 ＋ 解释器计数），再把这份文件换成陈旧版本——两通道**仍然一致**且都错，即证明该一致性不含信息；随后补一条直读源实体的通道，结论立刻分叉，才暴露同源。

### L36 少数被吞：聚合方式把失败信号吃掉
- **现象**：多通道结果不齐时，用「任一通过 / 多数通过 / 取最后一次 / 取并集」聚合 ⇒ 少数通道的 FAIL 被多数 PASS 覆盖，整体仍报成功。实测形态：某自检的检查项原先取两份清单的**并集**判「类别齐备」——删掉任一份的整个类别，另一份的同名类别会**掩护**它，检查**静默报 PASS**。与第 6 / 7 类同源：**一处信号被另一处的同类信号掩盖**，只不过掩盖发生在聚合这一步。
- **判据**：多通道一律**少数否决**——**任一通道报 FAIL 即整体降级**，不得用多数覆盖少数，也不许用「最后一次」顶替。分歧未归因前结论为**无法判定**；归因必须落到「哪条通道的哪个依赖失效」，不许用「大概率没问题」收尾。计数类断言另需对账总数（`达标数 == 总数`），缺一个即不算完成。
- **反例**：构造三通道结果 `True, True, False` —— 用 `any()`（任一通过）与「≥2 通过」（多数决）聚合**都报成功**，只有 `all()` 报失败。任一聚合式只要吞掉那个 `False`，即证明它不可用于本次判定。

### L37 一致地错：一致性的盲区必须显式标注
- **现象**：所有通道**一起错且互相印证**——它们共享同一个错误前提（指错了路径 / 解析到旧地址 / 用了同一份陈旧基线）。通道越多、越一致，结论看起来越可信，而**错误信息量一点没增加**。这是多通道验证的固有盲区，无法靠增加同源通道消除。
- **判据**：给结论时必须写明**一致性的来源**与**剩余盲区**（如「三条通道均读 `X`，而 `X` 本身未独立校验」）；同源 ⇒ 置信度按**单通道**计，**不得**写「已交叉验证」。**共同前提必须单独验一次**：目标路径是不是真对象、解析结果是不是目标实例、凭据是否在有效期内、是否绕过了缓存。
- **反例**：让多条通道都基于同一个错误前提（都指向 `assumed/` 这份陈旧副本）读同一个值——它们**全部成功且彼此一致**，但与真实对象 `real/` 的值矛盾；补一条不共享该前提的通道（直读生效实体）后分叉出现，即证明此前的一致是共同前提制造的，而非事实。

### L41 候选判据未经阴性对照就计入覆盖
- **现象**：新增判据只写了一行「反例：待补」，或反例命令压根跑不起来（rc=127 / 找不到命令 / 超时）。条目数照常 +1、类覆盖照常齐备，库**看起来更全了**，实际多了一条**恒不生效**的条目；更隐蔽的是「跑不起来」与「反例如期报错」在退出码上同形，自动检查会把前者当成通过。
- **判据**：新判据入库前必须过门——`scripts/candidate_gate.py verify` 实际执行反例命令并确认它**报出 FAIL 信号**；命令没跑起来（rc=127 / 超时 / 占位）一律**不算** FAIL 信号，须先修反例。跑不出 FAIL 的条目不入库，记入待修清单。
- **反例**：用 `new` 生成一份骨架候选（反例命令为占位符、来源留档为空），交给 `verify` —— 必须被拒（rc=1）。若这道门自己失效（骨架被判通过），说明门没守住。
- **反例准备**：`python3 {skill}/scripts/candidate_gate.py new --code L99 --title "占位" --out {tmp}/cand.md`
- **反例命令**：`python3 {skill}/scripts/candidate_gate.py verify {tmp}/cand.md`
- **反例判据**：`nonzero`
- **来源**：一次真实踩坑——反例命令若**根本跑不起来**（rc=127，命令名写错或占位未替换），与「反例如期报错」在退出码上完全同形 ⇒ 会被误判成「反例已报 FAIL」而放行；同时一条只写「待补」的反例，计数与「覆盖」照常 +1

## 类 7 续 · 证据不可复跑（L38–L40）

> 本族口径：**证据的价值不在它当下说服了你，而在别人能不采信你的措辞就复核它。**
> 前六类加第 7 类本体管的是「锚被误读 / 锚不存在」；本族管的是**锚留下了、却不可比对**——
> 证据里只有结论与回显，没有可机械复跑的东西。处置不是判失败，而是**结论降级**：
> 无判据的通道 ⇒ 无法判定；缺对照或复跑漂移 ⇒ 不得沿用旧结论。
> 落地做法（证据包六要素 + 三种降级）见 `references/方法详解.md` §五。

### L38 证据只有结论、没有可机械判定的期望
- **现象**：证据条目写的是「已确认 / 没问题 / 对得上」，没有读取命令、没有原始输出、**没有一条可机械判定的期望**。第三方拿到这份证据只能二选一：相信出具方，或重做一遍。⚠️ 与 **L32** 的区别：L32 是断言的**主体**不可定位（只有动作、没有对象）；本条是**对象有、判据不可执行**——看上去更完整，实际上同样无从复核。
- **判据**：每条证据必须同时给出 **① 读取命令 ② 原始输出（或其哈希）③ 一条可机械判定的期望**（输出须匹配的正则 / 期望退出码）；三者缺一即不可复核，结论落**无法判定**，不得以「已核对」通过。
- **反例**：用 `scripts/evidence_pack.py` 向证据包追加一条**只带结论**的通道（`add --channel D-只有结论 --cmd "echo v2"`，不给 `--expect-regex`）⇒ `replay` 报「**无法判定**：通道『D-只有结论』没有可机械判定的期望（只有结论、没有判据）—— 证据不可复核」；给同一条补上 `--expect-regex "v2"` 后转为 PASS。两种结果只差在**有没有判据**，即证明「已确认」本身不构成证据。

### L39 复跑漂移：对象或环境已变，旧结论被直接沿用
- **现象**：结论在取证那一刻成立，之后对象或环境变了，而证据里**没有可比对的东西**（无输出哈希 / 无读取时刻 / 无环境指纹）⇒ 重跑同一条命令会得到另一个输出，却**无从发现**，旧结论被原样搬到当下。⚠️ 与 **L34** 的区别：L34 是断言里**没有时刻**（无基准）；本条是证据里**有值但不可比对**（无法判断它是不是同一个值）。
- **判据**：证据必须带**输出哈希 + 读取时刻 + 环境指纹**；交给他人前先复跑一次，先比哈希再给结论。哈希变了即落**无法判定（复跑漂移）**，不许用「当时是对的」把旧结论搬到现在。
- **反例**：记一条输出每次都变的通道（`add --cmd "date +%s%N" --expect-regex "."`）⇒ `replay --execute` 报「**无法判定**：复跑输出与记录不一致（哈希漂移）—— 环境或对象已变，旧结论不可沿用」；换成确定性命令（`cat` 一个内容固定的文件）后，同一条复跑哈希稳定并给出「已证」。两者只差在**能不能比对**，即证明无哈希的证据不可复跑。

### L40 个性化判据未在本环境实测就照抄
- **现象**：判据库里带平台 / 版本前提的条目（「BSD grep 会…」「某 shell 会…」「受限环境看不到…」）被直接当成**本机结论**引用。这类判据的成立依赖环境，而环境恰恰是判据里唯一会变的那一项；照抄会把一条**别处的踩坑**变成**此处的错误断言**，且两个方向都会错（照抄说"会"、本机其实不会；照抄说"不会"、本机其实会）。
- **判据**：引用带环境前提的判据前，先在本环境跑一次它的反例（或用 `scripts/env_fingerprint.py` 读指纹）；**实测结果与判据描述不一致时按实测为准**，并在结论里写明「该判据在本环境不成立」。判据本身的建议（如一律 `grep -E`）不因实测不成立而作废——换环境即可能翻转。⚠️ **照抄是否真的危险，取决于该判据的前提在本机是否成立**：前提成立时照抄**碰巧对**、前提不成立时照抄**必然错**——两者都不是验证，只是运气；所以判据要写「先实测」，而不是「按书上说的改」。
- **反例**：先**实测**本环境的 BRE 交替支持（得 `fact`），再与判据库 L02 的**前提**（它假设"不支持"，记为 `unsupported`）比对 —— 不一致 ⇒ 照抄断言被实测证伪（**rc=1，报 FAIL**）；一致 ⇒ 该判据的前提在本机碰巧成立，照抄无害**但也未验证**（**rc=3，不报 FAIL**）。⚠️ 本反例**可证伪**：三态各有取值，既不恒报 FAIL、也不静默 PASS。
  > 反例改过两版、两版都错，方向不同病同一条（**没落在判据的维度上**）：① 旧版写死"计数应为 0"⇒ 换一类 grep 后**静默变成 PASS**（假通过）；② 中间版用 `grep -qv "$(cat fact)" fact` ⇒ 它问的是"文件里有没有它自己的内容"，`fact` 取任何值都 rc=1 ⇒ **恒报 FAIL**、不判定任何事实（假失败）。两版都照样能过入库门。
- **反例准备**：`printf 'a\nb\n' > {tmp}/s.txt; if [ "$(grep -c 'a\|b' {tmp}/s.txt)" = "0" ]; then echo unsupported > {tmp}/fact; else echo supported > {tmp}/fact; fi`
- **反例命令**：`sh -c 'f=$(cat {tmp}/fact); if [ "$f" = "unsupported" ]; then echo "照抄断言成立（前提在本机碰巧成立 ⇒ 无害，但也未验证）"; exit 3; fi; echo "FAIL 照抄断言(库前提=unsupported) 与实测(=$f) 矛盾 ⇒ 照抄个性化判据必然被证伪"; exit 1'`
- **反例判据**：`rc:1`
