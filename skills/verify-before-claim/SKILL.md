# 完成声明验证（verify-before-claim）

把「我以为改好了」换成「有证据证明改好了」。

## 定位

Agent 的执行链上有一类故障不报错：命令返回 0、工具回显成功、接口返回 200，
但目标对象**从来没变过**。这类假成功不产生异常，也就不会触发任何重试或告警。
本技能提供一套机械判据，在说出「完成」之前，先证明「检查通过」这件事本身不是假象。

## 何时用（适用 / 不适用）

- **用它**：改了文件 / 部署了服务 / 跑了脚本或定时任务 / 推了数据之后要确认**真的落地**；
  用户反馈「明明做了却没变化」而你手上只有一个自我汇报的结论；需要给出**可复核的证据链**。
- **不用它**：报错信息明确、失败原因已知（那是普通调试，直接读报错更快）；
  页面渲染类症状——浏览器侧证据优先（看 Console 报错与 Network 请求状态），不在本技能范围内。

## 触发词

- 没生效 / 改了没变 / 部署了没用 / 跑了但结果不对 / 返回空 / 还是旧的 / 数据没更新 / 看着跑完了但没效果

### 不触发

- 页面打不开 / 转圈 / 数字不对 / 白屏 —— 这些是浏览器渲染层症状，先取浏览器证据
  （Console 报错 / 请求状态码）定位，不在本技能范围内。本技能的边界是**执行链**：文件、服务器、
  定时任务、接口、仓库、推送链路。两边判据不可互换：服务端一切正常，页面照样可以是坏的。

## 核心资产一：报 PASS 的检查器，必须先自证能报 FAIL

任何检查器——检索命令、断言、校验脚本、自写的比对程序——在它报出 PASS 之前，
**必须先用一个必然失败的输入跑一遍，亲眼看到它报 FAIL**。

理由：检查器失效时的表现与「一切正常」**完全一样**。空结果、被吞掉的异常、
不匹配的模式、未加载的模块，产出的都是同一个 PASS。不跑阴性对照，
你采信的不是事实，是检查器的沉默。

阴性对照三选一（按成本递增）：

| 手段 | 做法 | 适用 |
|---|---|---|
| 已知反例 | 用一条确定错误 / 确定不存在的输入跑同一检查器，必须 FAIL | 首选，成本最低 |
| 定点 mutation | 临时改坏被测对象的一个特征位，确认检查器能发现 | 检查逻辑较复杂时 |
| 双通道对照 | 换一条**独立**路径（不同命令 / 不同接口）复测同一结论 | 前两者都做不了时 |

⚠️ 阴性对照自身也会假 FAIL：反例跑了 FAIL，先确认反例**真的**注入了，
而不是检查器在别处崩了。对照与被测对象唯一不同的变量，只能是你注入的那个。

## 核心资产二：五不信

| # | 不信 | 因为 | 改为 |
|---|---|---|---|
| 1 | 不信**空结果** | 工具静默失败与「确实没有」同形 | 先用已知存在的样本证明工具能命中 |
| 2 | 不信**无差异** | 加了过滤条件而样本量不变 ⇒ 过滤根本没生效 | 怀疑格式不匹配，回读中间产物 |
| 3 | 不信 **rc=0** | 退出码可被显式写成 0，与业务结果无关 | 去读实体（文件、行数、远端状态） |
| 4 | 不信**工具成功回显** | 回显来自工具自身，不代表落盘 | 改完立即用**另一条**命令回读特征串 |
| 5 | 不信**元数据** | 体积 / 时间 / 缓存字段会滞后或被子操作刷平 | 打开实体核对，不看目录列表字段 |

## Goal（可验证输出物）

一份**带证据的结论**，包含三样：

1. **定格后的断言**——一句可被证伪的话（「远端 `X` 已包含 `Y`」），不是「做完了」；
2. **阴性对照记录**——反例输入 + 它确实报了 FAIL；
3. **真检的原始输出片段**——执行了什么命令、看到什么关键行。

缺第 2 项时，结论的措辞必须降级为**「已执行但未验证」**。

## Inputs（必填 / 可选）

- **必填**：本次要宣告的结论（或用户报告的异常现象）。
- **可选**：目标对象的路径 / 可达方式（能自己拿到的就自己拿，不要求用户提供）；
  上次已知的良好状态（用于双通道对照）。

## Constraints（不做什么 + 质量门槛 + 逃逸条款）

- **不处理**：页面渲染类故障（转圈 / 白屏 / 元素不渲染）；报错信息已明确指向的失败
  （直接调试更快）；需要领域知识才能判断的业务正确性——只验「有没有落地」，不验「业务上对不对」。
- **不做什么**：不用产生该改动的**同一条路径**去验证它；不因为「检查通过了」就省略阴性对照；
  不把「无法验证」措辞成「已完成」。
- **质量门槛**：每条结论必须能追到一条命令 + 一段原始输出；阴性对照未通过时**不得**采信任何 PASS。
- **逃逸条款**：当本技能的要求与用户明确意图冲突、或环境根本不允许做该对照（如对象已不可达）时，
  优先保障用户数据与意图，并**显式说明偏离理由**与替代动作——不得静默偏离。

## 六类失败形态（判据索引）

| # | 形态 | 典型表象 | 判据库 |
|---|---|---|---|
| 1 | 空结果伪装成无问题 | 检索静默空；多模式交替语法在该平台不成立；截断式计数 | 本机与工具链 |
| 2 | 成功回显 ≠ 落盘 | 编辑工具回报成功却查不到；平台命令回显 ✓ 但不生效；工作目录漂移 | 本机与工具链 |
| 3 | 退出码 0 ≠ 成功 | 框架层把错误退出写成 0；空集合的全称判断恒真；传输命令 rc=0 却不落地 | 两份都涉及 |
| 4 | HTTP 200 ≠ 正确内容 | 签名失效但状态码仍是 200，错误写在响应体里 | 远端与接口 |
| 5 | 元数据 ≠ 实体 | 列表体积字段走缓存；时间字段被批量操作刷平 | 两份都涉及 |
| 6 | **探测失败 ≠ 对象不可用** | 缺代理绕过参数的假 502；shell 无 `/dev/tcp` 恒判 CLOSED；受限环境看不到服务；前端探测失败被读成「服务没在跑」 | 远端与接口 |

> 第 6 类的共同口径：**探测手段的失败，不能推断被探测对象的状态**。
> 判定「目标不可用」之前，必须先证明探测手段在该环境下**具备可用性**——
> 与阴性对照是同一件事的两个面。

## 步骤（读取 → 处理 → 验证）

1. **定格声明**：把即将说出的话写成一句可证伪的断言。
2. **定位形态**：查上表，确定这次最可能踩的是哪一类，取对应判据库。
3. **跑阴性对照**：先执行反例，确认检查器**能**报 FAIL。对照不过 ⇒ 停工修检查器，
   不许跳过（跳过等于把「无法验证」伪装成「已验证」）。
4. **跑真检**：对照通过后才采信 PASS，并保留原始输出片段。
5. **收口**：按 Goal 的三件套给结论；证据缺失的措辞降级为「已执行但未验证」。

## 判据库（按需加载）

| 信号（命中任一） | 加载哪份 | 在什么动作之前 | 不路由到（Do NOT route） |
|---|---|---|---|
| 改动落在本机文件 / 脚本 / 配置 / 受管服务，或涉及检索、计数、编辑工具回显、退出码 | `references/判据库-本机与工具链.md` | **在说出「改完了 / 跑通了」之前** | 页面渲染类症状（转圈 / 白屏 / 元素不渲染）→ 走浏览器侧排障 |
| 结论涉及远端服务器 / 定时任务 / 对象存储 / 在线接口 / 部署核验 / 可达性探测 | `references/判据库-远端与接口.md` | **在说出「部署完了 / 接口通了」之前** | 业务正确性判断（数据对不对、效果好不好）→ 属业务口径，不在本技能范围 |
| 两边都碰（本地改完推远端） | 两份都加载 | 按上两条分别收口 | 需要改代码才能修的问题 → 先调试定位，再回来验证 |

**不路由到本技能**：这两份都不解决「页面渲染不对」——那属浏览器侧排障。
本技能只回答一件事：动作到底有没有落到实体上。

## 依赖

- 无第三方依赖；不需要联网，不需要安装任何包。
- 判据用到的命令行工具（检索、请求、哈希、进程查询）均为系统自带。
  某条判据要求的工具在当前环境不存在时，先按该条的反例验证「工具可用」；
  不可用就换独立通道，不要退化成「跳过验证」。
- `scripts/assert_hits.py`：判据库自检（条目数 / 六类覆盖 / 每条三段齐备）。
  改过判据库后跑一次；`--self-test` 会先证明这个断言脚本**自己能报 FAIL**。

## 边界与安全

- **只读优先**：验证动作默认不改动被测对象。必须做 mutation 时，先记录原值并在验证后还原。
- **不越权**：不为了让检查通过而放宽权限、关闭校验开关或跳过安全钩子。
- **凭据**：验证过程不打印凭据明文，只给掩码或长度与前缀。
- **不可逆操作**：涉及删除 / 覆盖时先列影响面再执行；「删不掉」与「删了但空间没释放」
  是两种不同事实，措辞必须与实际一致。

## Verification Checklist

- [ ] 检查器跑过阴性对照，且对照确实报 FAIL
- [ ] 每条结论都有对应的命令与原始输出片段
- [ ] 验证走的是**独立通道**（不是产出该改动的同一条路径）
- [ ] 涉及远端 / 接口时，已排除探测手段本身失效（第 6 类）
- [ ] 无法验证的部分已显式声明为「未验证」，未被措辞吞掉

## 使用示例

> 用户：「改了配置，重启了吧？怎么感觉没生效。」

1. **定格**：「服务进程已加载新配置值 `V`」（而不是「重启过了」）。
2. **定位形态**：本机侧 → 第 2 类（成功回显 ≠ 落盘）。
3. **阴性对照**：先查一个**确定不存在**的值 `V_absent`，确认查询命令能报「无此值」。
   命令恒返回空 ⇒ 说明查询本身坏了，回上一步换命令。
4. **真检**：绕过本地代理直连端口读**生效值**，与配置文件比对；
   再看进程启动时间是否晚于配置文件的最后修改时间。
5. **收口**：「配置已加载，证据：进程启动时间 `T2` 晚于配置修改时间 `T1`，运行值 `V` 与文件一致」。
   若进程时间早于配置 ⇒ 结论是**没生效**，并给出重启动作。

## 常见错误

| 现象 | 真因 | 处置 |
|---|---|---|
| 多模式检索用交替转义符，返回空 | 该平台的检索不认这个语法，**静默**失配 | 改用扩展正则，或换检索工具 |
| 「我扫了一遍没找到」⇒ 判定不存在 | 空结果被当成事实 | 要么实测命中 0 并附命令，要么标「未验证」 |
| 验证走了产出改动的同一条路径 | 同源失败会互相掩护 | 换独立通道（另一进程 / 另一接口 / 直接读实体） |
| 把「探测失败」写成「对象不可用」 | 第 6 类形态 | 先自证探测手段在本环境可用 |
| 加了过滤条件但结果没变 | 两侧格式不统一，比较恒真 | 归一化后再比，并把「排除了 N 条」打进日志 |

## 速查

| 场景 | 最小判据 |
|---|---|
| 文件改动 | 用**另一次**读取回读特征串，不比时间戳 |
| 远端部署 | 在远端机器上读实体文件，不看传输命令回显 |
| shell 脚本 | 关键分支显式非零退出；错误路径单独测一次 |
| HTTP / 接口 | 判 200 之外，还要判**响应体内容**是否匹配预期格式 |
| 定时任务 | 看产出物的内容与时间，不看任务自身的成功日志 |
| 目录 / 清单 | 打开实体核对，不采信体积 / 更新时间字段 |
| 可达性探测 | 先绕过本地代理；再对一个**确定可用**的目标做同样的探测 |
