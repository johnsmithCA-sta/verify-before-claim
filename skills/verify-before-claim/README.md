# 完成声明验证（verify-before-claim）

在说出「改完 / 部署完 / 跑完」之前，先证明你的检查手段本身没有骗人。

## 解决什么问题

执行链上有一类故障不报错：命令返回 0、工具回显成功、接口返回 200，但目标对象**从来没变过**。
这类假成功不产生异常，因此不会触发重试或告警，只会以「已完成」的形式被收下。

## 核心方法：报 PASS 的检查器，必须先自证能报 FAIL

任何检查器——检索命令、断言、校验脚本、自写的比对程序——失效时的表现，
与「一切正常」**完全一样**：空结果、被吞掉的异常、不匹配的模式，产出的都是同一个 PASS。

所以在采信任何通过结论之前，先用一个**必然失败**的输入跑一遍，亲眼看到它报 FAIL。
跑不出 FAIL，说明这个检查器此刻不可用，它给出的 PASS 不作数。

配套的**五不信**：

1. 不信**空结果** —— 工具静默失败与「确实没有」同形
2. 不信**无差异** —— 加了过滤条件而样本量不变，说明过滤没生效
3. 不信**退出码** —— 退出码可被显式写成 0，与业务结果无关
4. 不信**工具成功回显** —— 回显来自工具自身，不代表落盘
5. 不信**元数据** —— 体积 / 时间 / 缓存字段会滞后或被别的操作刷平

## 覆盖范围

六类假成功形态：

| # | 形态 | 典型表象 |
|---|---|---|
| 1 | 空结果伪装成无问题 | 检索静默空；多模式语法不成立；截断式计数 |
| 2 | 成功回显 ≠ 落盘 | 编辑工具回报成功却查不到；平台命令回显 ✓ 但不生效 |
| 3 | 退出码 0 ≠ 成功 | 框架层把错误退出写成 0；空集合的全称判断恒真 |
| 4 | HTTP 200 ≠ 正确内容 | 签名失效但状态码仍是 200，错误写在响应体里 |
| 5 | 元数据 ≠ 实体 | 列表体积字段走缓存；时间字段被批量操作刷平 |
| 6 | 探测失败 ≠ 对象不可用 | 缺代理绕过参数的假 502；shell 无 `/dev/tcp` 恒判 CLOSED |

判据库共 **56 条**，每条都是三段式：**现象 → 判据 → 反例**。反例就是你自己的阴性对照。

## 什么时候用

- 改了文件 / 部署了服务 / 跑了脚本或定时任务 / 推了数据之后，要确认**真的落地**
- 你反馈「明明做了却没变化」，而手上只有一个自我汇报的结论
- 需要给出**可复核的证据链**时

## 什么时候不用

页面渲染类故障（打不开 / 转圈 / 白屏 / 数字不对）属浏览器侧问题，
先取浏览器证据（Console 报错 / 请求状态码）定位。本技能只回答一件事：
**动作到底有没有落到实体上**。

## 目录

- `SKILL.md` —— 方法、六类形态索引、执行步骤与检查清单
- `references/判据库-本机与工具链.md` —— 30 条，覆盖文件、脚本、编辑工具回显、退出码
- `references/判据库-远端与接口.md` —— 26 条，覆盖服务器、定时任务、对象存储、在线接口、可达性探测
- `scripts/assert_hits.py` —— 判据库自检（条目数 / 六类覆盖 / 每条三段齐备），带 `--self-test` 阴性对照

## 使用

判据是**读着用**的，不是跑着用的：命中哪一类形态就读哪一份判据库，按「判据」行动，
按「反例」先验证检查手段可用。

判据库自检：

```bash
python3 scripts/assert_hits.py              # 条目数 / 覆盖 / 三段齐备
python3 scripts/assert_hits.py --self-test  # 先证明这个断言脚本自己能报 FAIL
```
