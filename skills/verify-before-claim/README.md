# 完成声明验证（verify-before-claim）

在说出「改完 / 部署完 / 跑完」之前，先证明你的检查手段本身没有骗人。

## 解决什么问题

执行链上有一类故障不报错：命令返回 0、工具回显成功、接口返回 200，但目标对象**从来没变过**。
这类假成功不产生异常，因此不会触发重试或告警，只会以「已完成」的形式被收下。

## 核心方法：报 PASS 的检查器，必须先自证能报 FAIL

任何检查器——检索命令、断言、校验脚本、自写的比对程序——失效时的表现，
与「一切正常」**完全一样**：空结果、被吞掉的异常、不匹配的模式，产出的都是同一个 PASS。

所以在采信任何通过结论之前，先用一个**必然失败**的输入跑一遍，亲眼看到它报 FAIL。
跑不出 FAIL，说明这个检查器此刻不可用，它给出的 PASS 不作数。

配套的**五不信**：

1. 不信**空结果** —— 工具静默失败与「确实没有」同形
2. 不信**无差异** —— 加了过滤条件而样本量不变，说明过滤没生效
3. 不信**退出码** —— 退出码可被显式写成 0，与业务结果无关
4. 不信**工具成功回显** —— 回显来自工具自身，不代表落盘
5. 不信**元数据** —— 体积 / 时间 / 缓存字段会滞后或被别的操作刷平

## 覆盖范围

七类假成功形态：

| # | 形态 | 典型表象 |
|---|---|---|
| 1 | 空结果伪装成无问题 | 检索静默空；多模式语法不成立；截断式计数 |
| 2 | 成功回显 ≠ 落盘 | 编辑工具回报成功却查不到；平台命令回显 ✓ 但不生效 |
| 3 | 退出码 0 ≠ 成功 | 框架层把错误退出写成 0；空集合的全称判断恒真；多通道同源 ⇒ 一致恒真；聚合吞掉少数 FAIL |
| 4 | HTTP 200 ≠ 正确内容 | 签名失效但状态码仍是 200，错误写在响应体里 |
| 5 | 元数据 ≠ 实体 | 列表体积字段走缓存；时间字段被批量操作刷平 |
| 6 | 探测失败 ≠ 对象不可用 | 缺代理绕过参数的假 502；shell 无 `/dev/tcp` 恒判 CLOSED |
| 7 | 执行状态断言无锚可溯 | 「我已经检查过了」；「都改完了」；「已是最新」；证据在本地而断言说远端 |

判据库共 **76 条**，每条都是三段式：**现象 → 判据 → 反例**。反例就是你自己的阴性对照。

## 多通道验证的两条硬约束

用多条通道交叉验证时，「一致」本身并不自动可信：

1. **通道独立性** —— 两条通道若共用同一份中间产物、同一个缓存、同一个解析器或同一枚凭据，
   它们的输出就结构性相关，**一致是恒真的**（同源假一致）。采信前先列各通道的依赖链，
   并至少补一条**直读实体**的通道。
2. **少数否决** —— 结果不齐时，**任一通道报 FAIL 即整体降级**，不得用
   「多数通过 / 任一通过 / 取最后一次」把那条 FAIL 吃掉。全称断言还要对账总数
   （`达标数 == 总数`）。

另外，**一致性有固有盲区**：所有通道可能因同一个错误前提而「一致地错」——通道再多也不增加
信息量。所以结论必须写明**一致性的来源与剩余盲区**；同源的一致性按**单通道**置信度计，
不得写成「已交叉验证」。

## 结构化证据包（可交给别人复核）

一份结论的可信度，取决于别人能不能**不采信你的措辞**就复核它。证据包把一次验证落成一份 JSON：
**断言 + 锚（对象 / 范围 / 时刻）+ 通道 + 读取命令 + 原始输出与它的哈希 + 阴性对照 + 环境指纹**，
第三方可以离线核对，或在信任来源时**机械复跑**并独立得出结论。

```bash
python3 scripts/evidence_pack.py init --claim "远端 app 已是 v2" \
  --objective "app:/srv/app" --scope "3 个节点" --out pack.json
python3 scripts/evidence_pack.py add --pack pack.json --channel A-直读内容 \
  --cmd "ssh n1 'cat /srv/app/version'" --upstream "node1:/srv/app/version" --expect-regex "v2"
python3 scripts/evidence_pack.py add --pack pack.json --channel 对照-查不存在的串 \
  --cmd "ssh n1 'grep -c v9 /srv/app/version'" --upstream "node1:/srv/app/version" \
  --expect-regex "[1-9]" --control          # 这条必须报 FAIL
python3 scripts/evidence_pack.py replay --pack pack.json            # 离线核对（默认不执行命令）
python3 scripts/evidence_pack.py replay --pack pack.json --execute   # 机械复跑
```

三种降级：**没有可机械判定的期望** ⇒ 无法判定；**缺阴性对照** ⇒ 已执行但未验证；
**复跑输出哈希对不上** ⇒ 无法判定（对象或环境已变，旧结论不可沿用）。

## 环境自适配与判据自增长（半自动）

假成功形态**跨环境通用**，但「哪条判据会在本机命中」是**个性化**的。三层机制承接这两面：

| 层 | 做什么 | 脚本 |
|:--:|---|---|
| **1 环境指纹** | 探测本机环境，列出**本机已确认的陷阱**／**本环境不成立**／**未验证**三栏 | `scripts/env_fingerprint.py` |
| **2 入库门** | 新判据的反例**实跑出 FAIL** 才允许入库（编号接末尾、来源留档、拒绝推测型） | `scripts/candidate_gate.py` |
| **3 保留集回归** | 既有判据与全部脚本自检重跑，全绿才放行 | `candidate_gate.py regress` |

```bash
# 层 1：本机的判读规则是什么？别处的证据能不能用？
python3 scripts/env_fingerprint.py                       # 打印报告（默认不写文件）
python3 scripts/env_fingerprint.py --save ~/env-a.json
python3 scripts/env_fingerprint.py --diff a.json b.json   # 有关键差异 ⇒ 旧结论不可沿用（rc=2）

# 层 2+3：从一次真实踩坑沉淀一条判据
python3 scripts/candidate_gate.py new --code L42 --title "…" --out cand.md
python3 scripts/candidate_gate.py verify cand.md          # 反例必须实跑出 FAIL
python3 scripts/candidate_gate.py regress                 # 保留集全绿
python3 scripts/candidate_gate.py admit cand.md --apply   # 人工过闸
```

两条容易读错的口径：

- **「本环境不成立」≠ 这条判据没用** —— 例：macOS 的 BSD grep 实测**支持** BRE `\|` 交替，
  与该类判据描述的现象相反；正确读法是「在此环境不出现、换环境须复测」，而判据里的建议
  （一律 `grep -E`）仍然成立。
- **「未验证」≠ 「不适用」** —— 那是探测没跑起来，须换通道或显式写未验证。

⚠️ **`--apply` 要人显式敲出来，不是技术限制**：文献对"全自动改写判据库"的警告很明确——
对抗性输入会持续触发特定方向的改写，渐进劣化且难被发现。脚本负责**守门**，人负责**过闸**。
细节、五道闸门与三条显式盲区见 `references/判据自增长.md`。

## 输出三态

结论必定落在三态之一——不存在「做完了」这种说法：

| 结论态 | 含义 |
|---|---|
| **已证** | 断言有锚、阴性对照报了 FAIL、真检读到预期值 |
| **已证伪** | 读到与断言矛盾的值 |
| **无法判定** | 缺锚 / 对象不可达 / 对照跑不出 FAIL / 多通道分歧未归因——**合法且被鼓励**的结论 |

「无法判定」必须附**尝试过的命令**，否则等同回避。另注意：**「未找到」≠「不支持」**——
没读到证据，不等于事实是反面。

## 能力边界

**做**：核验**关于某实体可读状态**的断言——断言必须能**落回一条命令去读**
（文件 / 进程 / 接口响应体 / 仓库 / 平台包 / 定时任务产物）。

**不做**：

- 世界知识核查（那回答的是「话是不是真的」，不是「事是不是做了」；且需联网与知识源，会毁掉零依赖）
- 业务正确性、法律 / 医疗 / 投资结论
- 页面渲染类症状（归浏览器侧排障）
- 依赖模型内部状态的判断（logprobs、自报置信度）——**前沿模型正在陆续下线这些信号**

## 什么时候用

- 改了文件 / 部署了服务 / 跑了脚本或定时任务 / 推了数据之后，要确认**真的落地**
- 你反馈「明明做了却没变化」，而手上只有一个自我汇报的结论
- 需要给出**可复核的证据链**时

## 什么时候不用

页面渲染类故障（打不开 / 转圈 / 白屏 / 数字不对）属浏览器侧问题，
先取浏览器证据（Console 报错 / 请求状态码）定位。本技能只回答一件事：
**动作到底有没有落到实体上**。

## 使用

判据是**读着用**的，不是跑着用的：命中哪一类形态就读哪一份判据库，按「判据」行动，
按「反例」先验证检查手段可用。

判据库自检：

```bash
python3 scripts/assert_hits.py              # 条目数 / 覆盖 / 三段齐备
python3 scripts/assert_hits.py --self-test  # 先证明这个断言脚本自己能报 FAIL
python3 scripts/evidence_pack.py --self-test # 先证明证据包工具能报非「已证」
```
